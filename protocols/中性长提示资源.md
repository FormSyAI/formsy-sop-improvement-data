# 通用软件设计说明

本资料提供一般设计流程参考，不包含 FormSy 特定规则、评审标准或项目事实。

# 需求理解

先阅读项目事实，区分已确认决定、未知事项和建议。避免把建议写成用户决定。

# 状态与权限

设计应考虑角色、对象、前置状态、动作、后状态和可见结果。权限规则应能被实现和验证。

# 数据与接口

接口和数据模型应支持业务流程、错误处理和验收场景。技术选型应标注来源或建议。

# 验收设计

为关键流程设计正常和异常场景。反例应包含无效输入、权限不足、失败和恢复。

# 交付边界

输出设计草案，不声称实现、测试通过或用户确认。
