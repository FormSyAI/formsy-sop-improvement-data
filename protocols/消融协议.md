## 处理组

| 组 | 名称 | 系统资料 | 工作台 | 作用 |
|---|---|---|---|---|
| A | baseline | 无 | 不调用 | 原始基线 |
| B | neutral-long | 等长中性设计资料 | 不调用 | 排除提示长度本身影响 |
| C | main-sop | main 中 8 个 SOP 资源 | 不调用 | 检验 main SOP 资料的效应 |

不单独设置“SOP+工作台”stage1 组。原实验中宿主工作台调用发生在模型输出之后，不会改变第一阶段模型输入；该回执不能用于解释同一阶段输出质量差异。工作台作为流程证据链保留在原始报告中，不进入本消融因果解释。

## 案例与阶段

- 案例：设计稿送审与客户确认工具。
- 只跑第一阶段，输入来自原实验冻结的 `stage1.md`。
- 每组 3 个 seed：42、43、44。
- 总样本：3 组 × 3 seed = 9 次模型生成。

## 模型参数

- 模型：Qwen3-14B Q4_K_M，SHA-256 固定。
- llama 二进制与 tokenizer：使用既有固定二进制，SHA-256 固定。
- 上下文：32,768 tokens。
- 输出上限：4,096 tokens，包含 thinking 和最终答案。
- temperature：0.6。
- top_p：0.95。
- top_k：20。
- min_p：0。
- GPU layers：all。
- 逻辑 batch：256；物理 ubatch：128。该参数为 2026-11-02 本机资源适配项；默认 2048/512 在长 prompt 下触发 Metal OOM。三组全部使用同一 batch 配置，避免组间混杂。
- K/V cache：q8_0。
- flash attention：on。
- threads：4。

## 评审标准

只评审第一阶段。评分维度事先固定，不按篇幅、术语或模板数量加分。

### 事实保真（8 项）

1. 审核通过即自动发布。
2. 新版本发布后旧版本只读。
3. 意见和确认仅对最新发布版开放。
4. 历史完整保留。
5. 客户只能查看自己项目内已发布版本。
6. 修改意见必须绑定设计稿及版本。
7. 旧版本确认不继承到新版本。
8. 先处理意见再允许确认；处理或说明不采纳须留痕。

每项按：支持 / 冲突 / 未提及 / 不清楚 记录，并给输出定位。

### 反向缺陷（4 类）

1. 已定事实降级或重问。
2. 新增未标注假设或范围膨胀。
3. 状态/权限所有者错误。
4. 关键验收反例缺失。

每类记录：有 / 无、具体位置、严重级别 P0/P1/P2。

### 覆盖要求

必须检查的反例：

- 非本项目成员访问已发布版本。
- 客户访问未发布版本。
- 非指定客户确认人执行确认。
- 新版本发布后旧版本尝试确认或修改。
- 新版本未继承旧确认。
- 意见未处理时尝试确认。
- 修改申请被接受后原确认留痕并开启新一轮。
- 撤销访问后已下载副本仍保留。

### 成本

每组记录 prompt tokens、生成 tokens、耗时、EOG、输出字符数。

## 执行与停止

- 先对 9 个 prompt 做真实 tokenizer 预算审计；任何一条不 fit，先修订实验资料，不启动模型。
- 串行执行，不并行，避免 GPU 资源竞争。
- 每条输出必须完整 EOG；无 EOG 记为执行失败，不作为设计质量通过或失败。
- 输出为空、模型崩溃、GPU OOM、上下文溢出均记为环境/执行失败，保留证据，不计设计质量分。
- 不重跑、不覆盖、不挑选有利样本。

## 预期判读

1. 若 C 明显优于 A，而 B 不提升：支持 main SOP 资料带来事实保真提升。
2. 若 B 与 C 同时提升：差异可能主要来自长提示或更详细的一般要求，而非 SOP 语义。
3. 若 C 提升事实保真但范围膨胀增加：说明 SOP 有一致性收益，但需要范围约束。
4. 若三组均不稳定：说明模型执行能力是主要瓶颈，不能归因于 SOP。

## 边界

- 本实验只覆盖一个真实案例第一阶段。
- 每组 3 个 seed，只能观察组内稳定性，不能做强统计推断。
- 评审为静态文档评审，不执行代码、不部署、不用户验收。
- main-SOP 组仍是宿主注入文本，不是模型自主读取完整 SOP 或调用工作台。
- 不能由此证明“完整 SOP 流程”或“整个 SOP 仓库”有效。
