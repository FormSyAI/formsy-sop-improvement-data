# 设计稿送审与客户确认工具设计方案

## 一、业务理解
该工具旨在为设计工作流提供可视化管理平台，支持以下核心流程：
1. 设计师上传设计稿（支持图片/PDF格式）
2. 项目负责人审核并发布设计稿
3. 客户查看已发布版本并提出修改意见
4. 设计师根据意见修改并上传新版本
5. 客户确认最终版本
6. 完整保留所有版本历史和修改意见记录

系统需要支持多项目管理，每个项目包含：
- 多个设计稿（每个设计稿有多个版本）
- 审核流程记录
- 客户意见记录
- 确认状态追踪

## 二、规则与未知
### 明确规则
1. 身份管理：
   - 三类用户：设计师、项目负责人、客户
   - 身份绑定项目，可随时撤销访问
   - 每个项目指定1名客户确认人

2. 设计稿管理：
   - 支持图片/PDF上传
   - 每个设计稿可有多个版本
   - 新版本发布后，旧版本保持只读
   - 旧版本的确认状态不能继承到新版本

3. 审核流程：
   - 项目负责人审核通过即自动发布
   - 审核记录包含审核人、时间、状态

4. 客户交互：
   - 客户只能查看自己项目内的已发布版本
   - 意见必须关联特定设计稿和版本
   - 确认前需处理所有意见
   - 确认后如需修改，客户需提交修改申请

5. 数据保留：
   - 所有版本和意见历史完整保留
   - 撤销访问不影响已下载副本
   - 确认记录包含确认人、版本、时间

### 待确认问题
1. 项目成员权限：
   - 项目负责人是否可以同时是设计师？
   - 客户是否可以查看所有项目历史？

2. 意见处理：
   - 负责人标记意见处理状态的规则？
   - 是否需要跟踪意见处理进度？

3. 版本管理：
   - 新版本上传时如何处理命名冲突？
   - 版本历史保留期限？

4. 安全与权限：
   - 撤销访问后如何保证数据安全？
   - 是否需要审计日志？

5. 通知机制：
   - 除了现有沟通工具外是否需要其他通知方式？
   - 项目负责人审核通过时是否需要通知设计师？

## 三、关键状态及权限
| 状态类型 | 状态名称 | 权限说明 |
|---------|---------|---------|
| 项目状态 | 项目创建 | 所有用户可创建新项目 |
| 项目状态 | 项目关闭 | 项目负责人可关闭项目 |
| 设计稿状态 | 未上传 | 设计师可上传 |
| 设计稿状态 | 已上传 | 项目负责人可审核 |
| 设计稿状态 | 已发布 | 客户可查看 |
| 设计稿状态 | 已确认 | 客户可提交修改申请 |
| 意见状态 | 未处理 | 项目负责人可处理 |
| 意见状态 | 已处理 | 项目负责人可标记 |
| 意见状态 | 已确认 | 客户可确认 |
| 用户权限 | 设计师 | 上传设计稿 |
| 用户权限 | 项目负责人 | 审核、发布、处理意见 |
| 用户权限 | 客户 | 查看、提交意见、确认 |

## 四、数据与接口
### 核心数据模型
1. 项目(Projects)
   - ID
   - 名称
   - 创建时间
   - 负责人ID
   - 客户确认人ID
   - 成员列表

2. 设计稿(Designs)
   - ID
   - 项目ID
   - 上传人ID
   - 上传时间
   - 文件URL
   - 版本号
   - 状态(未上传/已上传/已发布/已确认)

3. 版本(DesignVersions)
   - ID
   - 设计稿ID
   - 版本号
   - 上传时间
   - 文件URL
   - 审核状态(待审/已审/已发布)
   - 审核人ID
   - 审核时间

4. 意见(Opinions)
   - ID
   - 项目ID
   - 设计稿ID
   - 版本号
   - 提交人ID
   - 提交时间
   - 内容
   - PDF页码(可选)
   - 处理状态(未处理/已处理/已确认)
   - 处理人ID
   - 处理时间
   - 处理说明

5. 确认记录(Confirmations)
   - ID
   - 项目ID
   - 设计稿ID
   - 版本号
   - 确认人ID
   - 确认时间
   - 修改申请ID(可选)

6. 修改申请(ModificationRequests)
   - ID
   - 项目ID
   - 设计稿ID
   - 版本号
   - 申请人ID
   - 申请时间
   - 状态(待审/已审/已修改)

### 核心接口
1. 项目管理接口
   - 创建项目
   - 获取项目详情
   - 修改项目设置
   - 删除项目

2. 设计稿管理接口
   - 上传设计稿
   - 获取设计稿列表
   - 获取设计稿详情
   - 审核设计稿
   - 发布设计稿
   - 获取版本历史

3. 意见管理接口
   - 提交意见
   - 获取意见列表
   - 处理意见
   - 获取处理记录

4. 确认管理接口
   - 确认版本
   - 获取确认记录
   - 提交修改申请
   - 获取修改申请状态

5. 用户管理接口
   - 添加/移除项目成员
   - 设置客户确认人
   - 撤销访问权限

## 六、可验证的验收场景
### 场景1：设计稿上传与审核流程
1. 设计师上传设计稿
2. 项目负责人审核设计稿
3. 审核通过后设计稿发布
4. 客户查看已发布设计稿
5. 验证：系统记录完整审核流程

### 场景2：意见提交与处理
1. 客户查看设计稿
2. 客户提交修改意见
3. 项目负责人处理意见
4. 验证：系统记录完整意见处理流程

### 场景3：版本确认与修改
1. 项目负责人发布新版本
2. 客户确认版本
3. 客户提交修改申请
4. 项目负责人接受申请
5. 验证：系统记录确认流程和修改申请流程

### 场景4：历史版本追溯
1. 查看某个设计稿的所有版本
2. 查看每个版本的审核和确认记录
3. 查看所有历史意见
4. 验证：系统完整保留所有历史数据

### 场景5：权限验证
1. 测试不同用户角色的访问权限
2. 验证撤销访问后的数据可访问性
3. 验证不同项目成员的权限范围
4. 验证客户只能查看自己项目的数据

## 七、技术自检
1. 数据完整性：所有操作都应有完整日志记录
2. 权限控制：所有操作都应经过权限验证
3. 版本控制：所有版本变更都应有完整记录
4. 意见跟踪：所有意见处理都应有完整记录
5. 确认流程：所有确认操作都应有完整记录
6. 历史保留：所有历史数据都应完整保留
7. 安全机制：所有敏感操作都应有安全验证
