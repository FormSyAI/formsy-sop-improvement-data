# 产品SOP自检方案：本模块相关部分

## 4. 产品专属检查规则 PC01–PC15

“主要层次”是建议，检查开始时结合对象固定实际所需层次。每项满足都附对象版本、定位和依据；PC 数量不是功能数量，不能把“15 项都写了”当作完整覆盖。

| ID | 检查与适用性 | 具体满足条件 | 主要层次与记录 | 依据 |
| --- | --- | --- | --- | --- |
| PC01 | 用户、问题与价值依据；所有项目 | 明确实际或拟定使用者、场景、任务、困难和预期收益；事实、用户表达、建议、假设及未知分开；价值主张不超出证据；需验证的关键假设有结果或明确阻塞 | L1/L2；关键主张按需 L3。用户／问题／证据表 | Q07/Q21；PS01/PS02/PS04 |
| PC02 | 产品目标和成功判断；所有项目 | 目标描述用户结果，和问题一致；目标来源明确；“好用、快、稳定”等有适用判断方式或待决定；数值有来源、单位、环境和口径，不编造商业指标 | L1/L2；效果判断按需 L3。目标及成功口径 | Q09/Q17；PS01/PS04/PS06 |

### 4.2 20261102 消融补充子规则

以下子规则是 PC03、PC04、PC08、PC10、PC12 的执行细化，不改变 PC01–PC15 编号和适用范围。

#### PC03.1 事实等级冻结

触发条件：任务输入中存在用户已确认的事实、决定或验收口径。

要求：

1. 输出前先将输入分为四类：已确认事实、用户假设、模型建议、真未知。
2. 已确认事实不得放入“待确认问题”。若确需追问，只能追问缺失边界，不得重问该事实是否成立。
3. 每条关键已确认事实应能在输出中定位承接位置，建议使用事实承接表。
4. 已确认事实之间冲突时，停止推进并列出冲突原文，不得静默选择其一。

#### PC03.2 范围增量守门

触发条件：输出中出现输入未给定的角色、能力、服务、通知、归档、备份、恢复、批量操作、管理员、自动化或存储策略。

要求：

1. 新增内容必须标记为“候选建议”，不得进入当前实施任务、接口清单或数据模型。
2. 明确说明其不在当前确认范围内，需用户确认后才升级为需求。
3. 技术上为实现已确认事实而必需的内部机制，标记为“技术必要”，并说明对应事实。
4. 不因通用最佳实践自动新增能力。

判定顺序：

1. 是否来自用户原文或有效决定？
2. 是否是实现某条已确认事实的技术必要条件？
3. 是否只是模型建议？

只有第 1 类进入当前范围；第 2 类进入技术设计并标注来源；第 3 类进入“候选建议，不进入本期范围”。

#### PC08.1 业务动作等价性

触发条件：已确认事实使用“即”“自动”“同时”“不得”“只”“仅”等强业务语义，或规定两个动作对外表现为一个结果。

要求：

1. 产品状态机和验收必须把该规则作为一个对外业务动作或一个原子状态转换承接。
2. 技术上可以拆成内部步骤，但中间状态不得暴露给用户，失败时不得留下违反业务语义的状态。
3. API 不得把已确认的等价动作拆成两个外部可选步骤，除非用户明确要求分步。
4. 验收必须覆盖成功转换和失败保留行为。

#### PC10.1 权限所有者矩阵

触发条件：同一对象存在多种角色，或同一动作存在不同权限结果。

要求：

1. 每个动作写清动作、对象、允许执行者、前置状态、成功结果、拒绝结果。
2. 区分查看、下载、提意见、确认、审核、发布、撤销访问等动作，不得把不同权限合并成“某类角色都可以”。
3. 拒绝路径必须可见并进入验收。
4. 权限规则必须绑定具体对象版本或对象状态。

#### PC12.1 规则反例验收

触发条件：已确认事实包含权限、状态、版本、顺序或副作用规则。

要求：

1. 按规则类型选取必要反例，不要求为每条规则机械堆叠用例。
2. 反例按风险触发：项目隔离规则测跨项目访问；版本规则测旧版本操作和状态继承；权限规则测非授权角色；顺序规则测前置未满足；副作用规则测撤销访问后的外部副本。
3. 反例必须写明期望拒绝或期望不变量，不得只写“验证失败”。

### 4.1 避免误判

- 有效用户表达可以支持“这是该用户提出的需求”，不能扩展成“所有同类用户都需要”。
- PC01/PC11 要求如实呈现证据程度；诚实说明假设并不自动证明产品价值。若该假设是必需交接条件，未验证时对应条件仍不满足或未核查。
- PC12 检查验收设计，不要求产品测试已经执行。真实测试是另一份结果记录；有测试设计不能记实际通过。
- PC15 检查台账合规，不要求所有问题已经解决。记录完整可以满足记录项，未解决的必需条件和对应阻塞仍存在。
- 不适用需要功能范围和理由；无资料、未完成、缺环境或难以检查都不能写不适用。
- 产品规则不能复制为未经确认的“行业最佳实践”；网上建议须说明采用理由与影响。
