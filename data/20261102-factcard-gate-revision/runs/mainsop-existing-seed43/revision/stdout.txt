# 设计稿送审与客户确认工具设计方案（修订版）

## 一、业务理解
本工具旨在为设计团队提供一个可视化的设计稿送审流程，支持多角色协作：
1. **设计师**：上传设计稿并维护版本迭代
2. **项目负责人**：审核设计稿并控制发布流程
3. **客户**：查看设计稿、提出修改意见并最终确认版本

工具需要支持以下核心流程：
- 设计稿上传与版本管理
- 审核流程与发布控制
- 客户意见收集与处理
- 版本确认与修改流程
- 历史记录与追溯

## 二、规则与未知

### 明确规则
1. **项目结构**：每个项目有唯一客户确认人，其他客户成员可提交意见
2. **版本控制**：
   - 每个设计稿可有多个版本
   - 新版本发布后，旧版本保持只读状态
   - 客户确认仅针对最新发布版本
   - 旧版本的确认不能继承到新版本
   - 历史记录完整保留（F04）
3. **审核流程**：
   - 审核通过即自动发布（F01）
   - 审核人可记录处理意见或说明不采纳
   - 审核记录包含审核人、时间、处理状态
4. **客户流程**：
   - 客户可对最新版本提出修改意见
   - 意见需关联具体设计稿和版本（F06）
   - 客户确认后如需修改，需提交重新修改申请
   - 原确认记录保留并标明后续修改
   - 撤销访问后客户仍可查看已下载副本（F10）

### 待确认问题
1. **文件格式支持**：是否支持矢量图格式（如SVG）？
2. **版本控制策略**：
   - 是否需要版本号或自动增量编号？
   - 是否支持版本回滚？
3. **意见处理流程**：
   - 审核人处理意见是否需要标记为"已处理"？
   - 处理意见是否需要有具体修改建议？
4. **权限控制**：
   - 客户是否能看到所有项目成员的审核记录？
   - 客户是否能查看所有版本的修改历史？

## 三、关键状态与权限

### 状态定义
1. **设计稿状态**：
   - 未上传
   - 已上传（待审核）
   - 审核通过（已发布）
   - 审核未通过
   - 已确认（最终版本）

2. **意见状态**：
   - 已提交
   - 已处理（负责人处理）
   - 已采纳（修改后重新发布）
   - 已驳回

3. **项目状态**：
   - 活动中
   - 已关闭（确认完成）

### 权限模型
| 角色         | 权限范围                                      |
|--------------|-----------------------------------------------|
| 设计师       | 上传设计稿、维护版本、查看项目成员记录        |
| 项目负责人   | 审核设计稿、控制发布、处理客户意见、查看历史  |
| 客户确认人   | 查看已发布版本、提交修改意见、确认最终版本    |
| 其他客户     | 查看已发布版本、提交修改意见（非确认人）      |

## 四、数据与接口

### 数据模型
1. **项目(Projects)**
   - id (主键)
   - name
   - client_confirmer (客户确认人ID)
   - status (项目状态)
   - created_at
   - updated_at

2. **设计稿(Designs)**
   - id (主键)
   - project_id
   - file_url (文件路径)
   - file_type (文件类型)
   - uploaded_by (上传人ID)
   - uploaded_at
   - version (版本号)
   - status (状态)

3. **审核记录(Approvals)**
   - id (主键)
   - design_id
   - approver_id (审核人ID)
   - approval_status (审核状态)
   - approval_comment (审核意见)
   - approved_at

4. **意见(Comments)**
   - id (主键)
   - design_id
   - version_id (绑定版本)
   - commentor_id (意见提交人ID)
   - comment_text (意见内容)
   - pdf_page (可选PDF页码)
   - status (意见状态)
   - created_at
   - updated_at

5. **确认记录(Confirmations)**
   - id (主键)
   - design_id
   - version_id (绑定版本)
   - confirmer_id (确认人ID)
   - confirmation_status (确认状态)
   - confirmed_at

6. **修改申请(ModificationRequests)**
   - id (主键)
   - design_id
   - version_id (绑定版本)
   - requester_id (申请修改人ID)
   - request_text (修改请求)
   - status (申请状态)
   - created_at
   - updated_at

### 接口设计
1. **项目接口**
   - GET /projects - 获取项目列表
   - GET /projects/{id} - 获取项目详情
   - POST /projects - 创建新项目

2. **设计稿接口**
   - POST /designs - 上传新设计稿
   - GET /designs - 获取设计稿列表
   - GET /designs/{id} - 获取设计稿详情
   - PUT /designs/{id}/status - 更新设计稿状态

3. **审核接口**
   - POST /approvals - 提交审核
   - GET /approvals - 获取审核记录
   - PUT /approvals/{id}/status - 更新审核状态

4. **意见接口**
   - POST /comments - 提交意见
   - GET /comments - 获取意见列表
   - PUT /comments/{id}/status - 更新意见状态

5. **确认接口**
   - POST /confirmations - 提交确认
   - GET /confirmations - 获取确认记录

6. **修改申请接口**
   - POST /modification-requests - 提交修改申请
   - GET /modification-requests - 获取修改申请列表
   - PUT /modification-requests/{id}/status - 更新申请状态
