# 设计稿送审与客户确认工具设计方案（修订版）

## 一、业务理解

本系统服务于设计流程管理，主要涉及以下角色：

1. **设计师**：负责上传设计稿并维护版本
2. **项目负责人**：负责审核设计稿并发布
3. **客户**：负责查看设计稿并提出修改意见或确认版本

系统需要支持以下核心流程：
- 设计稿上传与版本管理
- 项目负责人审核流程
- 客户意见提交与确认流程
- 版本历史与修改记录管理

## 二、规则与未知

### 明确规则（已确认事实）
1. F01 审核通过即自动发布
2. F02 新版本发布后，旧版本只读
3. F03 意见和确认仅对最新发布版开放
4. F04 历史完整保留
5. F05 客户只能查看自己项目内已发布版本
6. F06 修改意见必须绑定具体设计稿及版本
7. F07 旧版本确认不继承到新版本
8. F08 先处理意见，才允许客户确认人确认
9. F09 每项目指定一名客户确认人；其他客户可提意见，不能确认
10. F10 撤销访问不能收回已下载副本

### 未知事项
1. 是否需要支持多版本并行评审？
2. 是否需要支持文件类型除PDF和图片？
3. 是否需要支持历史版本恢复？
4. 是否需要支持设计稿水印或权限控制？
5. 是否需要支持移动端专用功能？

## 三、关键状态及权限

### 状态机设计

| 状态 | 描述 | 触发条件 |
|------|------|----------|
| 上传中 | 设计师正在上传设计稿 | 新建设计稿 |
| 待审核 | 等待项目负责人审核 | 上传完成 |
| 已发布 | 设计稿已通过审核并发布 | 审核通过 |
| 待确认 | 等待客户确认 | 已发布 |
| 已确认 | 客户已确认设计稿 | 客户确认 |
| 待修改 | 需要修改设计稿 | 客户提交修改申请 |
| 已修改 | 设计稿已修改并发布 | 修改申请通过 |

### 权限模型（区分客户确认人和其他客户）

| 角色 | 权限 |
|------|------|
| 设计师 | 上传设计稿，维护版本 |
| 项目负责人 | 审核设计稿，发布版本 |
| 客户（非确认人） | 查看设计稿，提交修改意见 |
| 客户确认人 | 查看设计稿，提交修改意见，确认版本 |
| 管理员 | （未进入本期范围）管理项目成员，撤销访问权限 |

## 四、数据与接口

### 核心数据模型

1. **项目 (Project)**
   - ID
   - 名称
   - 客户确认人ID
   - 成员列表
   - 创建时间

2. **设计稿 (Design)**
   - ID
   - 项目ID
   - 文件名
   - 文件类型
   - 上传时间
   - 上传人
   - 最新版本ID
   - 状态

3. **版本 (Version)**
   - ID
   - 设计稿ID
   - 版本号
   - 文件
   - 上传时间
   - 状态（已发布/已归档）

4. **意见 (Comment)**
   - ID
   - 项目ID
   - 设计稿ID
   - 版本ID（F06）
   - 内容
   - 页码
   - 提交人
   - 提交时间
   - 状态（待处理/已处理）

5. **确认记录 (Confirmation)**
   - ID
   - 项目ID
   - 设计稿ID
   - 版本ID（F03）
   - 确认人
   - 确认时间
   - 状态（已确认）

6. **修改申请 (ModificationRequest)**
   - ID
   - 项目ID
   - 设计稿ID
   - 版本ID（F06）
   - 申请内容
   - 申请人
   - 申请时间
   - 状态（待处理/已处理）

### 接口设计（绑定version_id）

1. **设计稿审核发布接口**
   - POST /designs/{designId}/review
   - 参数：审核结果
   - 返回：设计稿状态（F01自动发布）

2. **意见提交接口**
   - POST /comments
   - 参数：项目ID、设计稿ID、版本ID（F06）、内容、页码
   - 返回：意见ID

3. **确认接口**
   - POST /confirmations
   - 参数：项目ID、设计稿ID、版本ID（F03）
   - 返回：确认状态（F08先处理意见）

4. **修改申请接口**
   - POST /modificationRequests
   - 参数：项目ID、设计稿ID、版本ID（F06）、申请内容
   - 返回：申请ID

## 六、可验证的验收场景

1. **审核自动发布**
   - 项目负责人审核通过后，系统自动发布设计稿（F01）
   - 旧版本变为只读状态（F02）

2. **版本绑定验证**
   - 意见提交时必须绑定具体版本ID（F06）
   - 确认操作仅对最新发布版本开放（F03）

3. **确认权限验证**
   - 仅客户确认人可执行确认操作（F09）
   - 其他客户只能提交意见（F09）

4. **历史保留验证**
   - 新版本发布后，旧版本和旧意见保留（F04）
   - 旧版本确认记录不继承到新版本（F07）

5. **访问控制验证**
   - 客户仅能查看自己项目内已发布的版本（F05）
   - 撤销访问后已下载副本仍可访问（F10）
