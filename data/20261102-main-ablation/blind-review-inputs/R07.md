# 设计稿送审与客户确认工具设计方案（实验设计阶段）

---

## 一、业务理解

工具旨在为设计工作流程提供一个可视化、可追踪的协作平台，支持以下角色和操作：

- **设计师**：上传设计稿并维护版本。
- **项目负责人**：审核设计稿并决定是否发布给客户。
- **客户**：查看已发布版本，提出修改意见或确认版本。
- **项目**：作为组织单位，包含多个设计稿和版本。

工具需满足以下核心流程：

1. 设计师上传设计稿，生成初始版本。
2. 项目负责人审核设计稿，并决定是否发布。
3. 客户查看已发布版本，提出修改意见或确认版本。
4. 修改意见需与特定设计稿及版本绑定。
5. 新版本发布后，保留旧版本，且旧版本的确认不能等同于新版本已确认。
6. 修改需通过客户提交申请，并由负责人开启新一轮流程。

---

## 二、规则与未知

### 已知规则：

- 每个项目可以有多个设计稿。
- 每个设计稿可以有多个版本，每个版本可独立发布。
- 客户只能查看自己项目内已发布的版本。
- 修改意见必须与具体设计稿及版本绑定。
- 旧版本与旧意见保留，不被覆盖。
- 旧版本确认不等同于新版本确认。
- 客户确认后如需修改，需客户提交申请，负责人接受后开启新一轮流程。
- 意见需先处理，确认才能进行。
- 负责人处理意见后，需标记已处理或说明不采纳，并保留记录。
- 意见支持文字内容，可选绑定PDF页码。
- 允许下载，但撤销访问后无法收回已下载副本。
- 负责人可复制项目入口，通过现有沟通工具通知客户，不自动发消息。
- 负责人可自审并记录上传人和审核人。

### 未知问题（待确认）：

1. **客户确认人**是否唯一？是否允许多个客户确认人？是否有权限管理机制？
2. **客户提交修改申请后**，是否允许客户自行上传新版本？是否需由设计师上传？
3. **项目负责人审核**是否需通过审批流程？是否有审批层级？
4. **客户意见是否支持附件上传**？是否支持图片、PDF或其他格式？
5. **是否支持多语言界面**？是否需要考虑国际化支持？
6. **是否支持移动端与网页端的同步**？是否需要考虑响应式设计？
7. **是否需要支持项目归档或删除**？归档后是否仍保留历史记录？
8. **设计稿上传格式限制**？是否支持多种格式（如 PNG、JPG、PDF、PSD 等）？
9. **是否支持版本对比功能**？是否支持查看版本差异？
10. **是否支持项目成员权限细分**？如：仅允许查看、不允许上传等。

## 三、关键状态与权限

| 角色               | 权限/状态描述                                                                 |
|--------------------|-------------------------------------------------------------------------------|
| **设计师**         | 上传设计稿，创建版本，维护设计稿内容，查看所有版本及历史记录。              |
| **项目负责人**     | 审核设计稿，决定是否发布，处理客户意见，标记处理状态，复制项目入口，自审记录。 |
| **客户**           | 仅查看已发布版本，提出修改意见，确认版本，提交修改申请，查看历史记录。        |
| **项目**           | 作为组织单位，包含多个设计稿和版本，可被复制、归档或删除。                   |
| **设计稿**         | 可有多个版本，可发布或未发布，支持查看、下载、历史版本。                    |
| **版本**           | 可发布或未发布，可被客户查看、确认，支持修改意见绑定，保留历史记录。         |
| **客户确认人**     | 项目中指定的唯一客户确认人，负责最终确认设计稿版本。                         |
| **客户成员**       | 其他客户成员可提出修改意见，但不可确认版本。                                  |

## 四、数据与接口设计

### 数据模型

#### 1. 项目（Project）

- `id`：主键
- `name`：项目名称
- `created_by`：创建人
- `created_at`：创建时间
- `updated_at`：最后更新时间
- `status`：状态（如：活跃、归档、删除）
- `client_confirmation_person`：客户确认人（外键）
- `members`：成员列表（含角色）

#### 2. 设计稿（Design）

- `id`：主键
- `project_id`：所属项目
- `name`：设计稿名称
- `created_by`：上传人
- `created_at`：上传时间
- `versions`：版本列表（外键）

#### 3. 版本（Version）

- `id`：主键
- `design_id`：所属设计稿
- `version_number`：版本号
- `content`：内容（如文件路径或链接）
- `status`：状态（如：草稿、已发布、已确认、已修改）
- `published_at`：发布时间
- `confirmed_at`：确认时间
- `confirmed_by`：确认人
- `uploaded_by`：上传人
- `reviewed_by`：审核人

#### 4. 客户意见（ClientFeedback）

- `id`：主键
- `version_id`：关联版本
- `client_id`：客户
- `content`：意见内容
- `page_number`：PDF页码（可选）
- `status`：状态（如：待处理、已处理、已采纳、已拒绝）
- `handled_by`：处理人
- `handled_at`：处理时间
- `note`：处理说明

#### 5. 项目成员（ProjectMember）

- `id`：主键
- `project_id`：所属项目
- `user_id`：用户
- `role`：角色（如：设计师、负责人、客户）
- `access_level`：访问级别（如：只读、可上传、可审核）

## 五、主要实施任务

1. **用户系统与权限管理**：实现登录、角色绑定、项目成员管理、权限控制。
2. **项目与设计稿管理**：支持创建、编辑、归档、删除项目与设计稿。
3. **版本管理**：支持版本创建、上传、审核、发布、确认、修改流程。
4. **客户意见管理**：支持意见提交、绑定版本、处理状态、记录处理人与说明。
5. **客户确认流程**：支持确认、重新申请修改、记录确认人与时间。
6. **历史记录与留痕**：记录所有操作、审核、确认、修改、处理等事件。
7. **界面与交互**：提供网页与移动端适配的界面，支持查看设计稿、版本、意见、确认等。
8. **文件上传与下载**：支持多种格式上传，保留历史版本，允许下载。
9. **项目复制与入口共享**：支持复制项目入口，通过现有沟通工具通知客户。

## 六、可验证的验收场景

1. **设计师上传设计稿**：上传成功，生成初始版本，状态为草稿。
2. **负责人审核并发布**：审核通过后，版本状态变为已发布，客户可查看。
3. **客户提出修改意见**：意见成功绑定版本，状态为待处理。
4. **负责人处理意见**：处理后标记为已处理或已采纳，保留记录。
5. **客户确认版本**：确认后版本状态变为已确认，记录确认人与时间。
6. **客户提交修改申请**：申请后负责人接受，开启新一轮流程，保留原确认记录。
7. **新版本发布**：新版本发布后，旧版本仍保留，客户只能查看已发布版本。
8. **撤销访问后仍保留下载副本**：客户下载后撤销访问，仍能保留副本。
9. **项目复制入口**：复制后通过现有沟通工具通知客户，不自动发送消息。
10. **历史记录完整**：所有操作、审核、确认、修改、处理等事件均被记录。
