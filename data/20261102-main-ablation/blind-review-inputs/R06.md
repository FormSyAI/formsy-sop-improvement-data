# 设计稿送审与客户确认工具设计方案

## 一、业务理解

本系统服务于设计流程管理，主要涉及以下角色：

1. **设计师**：负责上传设计稿并维护版本
2. **项目负责人**：负责审核设计稿并发布
3. **客户**：负责查看设计稿并提出修改意见或确认版本

系统需要支持以下核心流程：
- 设计稿上传与版本管理
- 项目负责人审核流程
- 客户意见提交与确认流程
- 版本历史与修改记录管理

## 二、规则与未知

### 明确规则
1. 每个项目必须指定一个客户确认人
2. 客户只能查看自己项目内已发布的版本
3. 修改意见必须关联具体设计稿及版本
4. 新版本发布后，旧版本与旧意见保留
5. 旧版本的确认不能直接算作新版本已确认
6. 客户确认后需要修改时，客户提交重新修改申请
7. 负责人接受后开启新一轮
8. 原确认保留并标明后续修改
9. 先处理意见再允许确认
10. 负责人标记已处理或说明不采纳，保留记录
11. 文字意见，可选 PDF 页码
12. 允许下载，撤销访问不能收回已下载副本
13. 负责人复制项目入口，用现有沟通工具告知
14. 允许自审并记录上传人和审核人

### 未知事项
1. 是否需要支持多版本并行评审？
2. 是否需要支持批量上传设计稿？
3. 是否需要支持文件类型除PDF和图片？
4. 是否需要支持版本对比功能？
5. 是否需要支持多客户同时评审？
6. 是否需要支持意见优先级排序？
7. 是否需要支持修改申请审批流程？
8. 是否需要支持历史版本恢复？
9. 是否需要支持设计稿水印或权限控制？
10. 是否需要支持移动端专用功能？

## 三、关键状态及权限

### 状态机设计

| 状态 | 描述 | 触发条件 |
|------|------|----------|
| 上传中 | 设计师正在上传设计稿 | 新建设计稿 |
| 待审核 | 等待项目负责人审核 | 上传完成 |
| 已发布 | 设计稿已通过审核并发布 | 审核通过 |
| 待确认 | 等待客户确认 | 已发布 |
| 已确认 | 客户已确认设计稿 | 客户确认 |
| 待修改 | 需要修改设计稿 | 客户提交修改申请 |
| 已修改 | 设计稿已修改并发布 | 修改申请通过 |

### 权限模型

| 角色 | 权限 |
|------|------|
| 设计师 | 上传设计稿，维护版本 |
| 项目负责人 | 审核设计稿，发布版本 |
| 客户 | 查看设计稿，提交修改意见，确认版本 |
| 管理员 | 管理项目成员，撤销访问权限 |

## 四、数据与接口

### 核心数据模型

1. **项目 (Project)**
   - ID
   - 名称
   - 客户确认人
   - 成员列表
   - 创建时间

2. **设计稿 (Design)**
   - ID
   - 项目ID
   - 文件名
   - 文件类型
   - 上传时间
   - 上传人
   - 版本号
   - 状态

3. **版本 (Version)**
   - ID
   - 设计稿ID
   - 版本号
   - 文件
   - 上传时间
   - 状态

4. **意见 (Comment)**
   - ID
   - 项目ID
   - 设计稿ID
   - 版本号
   - 内容
   - 页码
   - 提交人
   - 提交时间
   - 状态

5. **确认记录 (Confirmation)**
   - ID
   - 项目ID
   - 设计稿ID
   - 版本号
   - 确认人
   - 确认时间
   - 状态

6. **修改申请 (ModificationRequest)**
   - ID
   - 项目ID
   - 设计稿ID
   - 版本号
   - 申请内容
   - 申请人
   - 申请时间
   - 状态

### 接口设计

1. **设计稿上传接口**
   - POST /designs
   - 参数：项目ID、文件、版本号
   - 返回：设计稿ID

2. **设计稿审核接口**
   - POST /designs/{designId}/review
   - 参数：审核结果
   - 返回：审核状态

3. **设计稿发布接口**
   - POST /designs/{designId}/publish
   - 参数：无
   - 返回：发布状态

4. **意见提交接口**
   - POST /comments
   - 参数：项目ID、设计稿ID、版本号、内容、页码
   - 返回：意见ID

5. **确认接口**
   - POST /confirmations
   - 参数：项目ID、设计稿ID、版本号
   - 返回：确认状态

6. **修改申请接口**
   - POST /modificationRequests
   - 参数：项目ID、设计稿ID、版本号、申请内容
   - 返回：申请ID

## 六、可验证的验收场景

1. **设计稿上传与版本管理**
   - 设计师上传设计稿
   - 系统生成版本号
   - 系统记录上传人和上传时间

2. **审核流程**
   - 项目负责人审核设计稿
   - 系统记录审核结果
   - 系统更新设计稿状态

3. **发布流程**
   - 项目负责人发布设计稿
   - 系统更新设计稿状态
   - 系统记录发布人和发布时间

4. **意见提交**
   - 客户提交修改意见
   - 系统记录意见内容、页码、提交人
   - 系统更新意见状态

5. **确认流程**
   - 客户确认设计稿
   - 系统记录确认人、确认时间
   - 系统更新确认状态

6. **修改申请**
   - 客户提交修改申请
   - 项目负责人审批申请
   - 系统更新修改申请状态

7. **历史记录**
   - 查看设计稿历史版本
   - 查看意见历史
   - 查看确认历史
   - 查看修改申请历史

8. **权限控制**
   - 客户只能查看自己项目内已发布的版本
   - 项目负责人只能审核指定项目的设计稿
   - 管理员可以管理项目成员和撤销访问权限
