# 设计稿送审与客户确认工具设计方案

## 一、业务理解
本系统需支持设计稿的版本化管理、多角色协作与确认流程。核心流程：
1. 设计师上传设计稿（含图片/PDF）
2. 负责人审核后发布版本
3. 客户查看已发布版本并提出修改意见
4. 新版本发布后保留历史版本与历史意见
5. 客户确认需在处理完所有意见后完成

## 二、规则与未知
### 已确认规则
- 角色体系：设计师/负责人/客户（客户需指定确认人）
- 版本管理：每个设计稿可有多个版本，新版本发布后旧版本只读
- 意见关联：必须绑定具体设计稿和版本
- 确认流程：需先处理所有意见，负责人标记处理状态
- 历史保留：所有版本、意见、确认记录永久保存
- 下载权限：客户可下载已发布版本，但无法撤销已下载副本

### 待确认问题
1. 客户确认后若需修改，是否需要负责人重新审核？（当前规则未明确）
2. 是否支持多项目并行处理？（当前仅提到"项目"但未说明数量限制）
3. 版本回滚机制：是否允许恢复到旧版本？（当前规则未提及）
4. 意见处理状态的可见性：客户能否查看意见处理进度？（当前规则未明确）
5. 客户确认后的新版本是否需要重新处理历史意见？（当前规则未明确）

## 三、关键状态与权限
| 角色       | 状态             | 权限操作                          |
|------------|------------------|-----------------------------------|
| 设计师     | 上传设计稿       | 创建新设计稿，上传文件           |
|            | 新版本创建       | 上传新版本，填写版本说明         |
| 负责人     | 审核中           | 审核设计稿，决定是否发布         |
|            | 已发布           | 发布新版本，处理客户意见         |
|            | 意见处理中       | 标记意见为已处理/不采纳          |
| 客户       | 已发布           | 查看已发布版本，提交修改意见     |
|            | 意见待处理       | 仅可查看当前版本的未处理意见     |
|            | 确认完成         | 仅可查看历史确认记录             |

### 核心接口
1. `/api/projects` - 项目管理（创建/查看/成员管理）
2. `/api/design-drafts` - 设计稿管理（上传/版本控制）
3. `/api/comments` - 意见管理（提交/处理状态）
4. `/api/confirmations` - 确认记录查询
5. `/api/version-history` - 版本历史查询

## 六、可验证验收场景
### 正常流程
1. 设计师上传设计稿，负责人审核后发布版本
2. 客户查看已发布版本，提交关联意见
3. 负责人处理意见后，客户确认当前版本
4. 新版本发布后，旧版本与历史意见仍可查看

### 异常/边界场景
1. 客户尝试查看未发布的版本 → 无权限
2. 提交意见时未关联具体版本 → 拦截提示
3. 新版本发布后尝试修改旧版本 → 操作失败
4. 客户确认前提交新版本 → 确认操作失败
5. 撤销访问后尝试下载已发布版本 → 允许下载（但无法访问系统）
6. 多个客户同时提交意见 → 系统记录所有意见
