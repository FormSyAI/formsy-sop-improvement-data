# 设计稿送审与客户确认工具设计方案

## 一、业务理解

本系统是面向设计工作流程的协作工具，包含三个主要角色：设计师、项目负责人、客户。系统核心功能包括设计稿上传、版本管理、意见收集、确认流程和版本控制。

系统需满足以下核心需求：
1. 支持多项目管理，每个项目有指定的客户确认人
2. 支持多版本设计稿管理，包含版本历史追溯
3. 实现意见收集与处理流程
4. 实现确认流程管理，包含确认人指定和确认记录
5. 实现版本控制，确保旧版本与旧意见的保留
6. 支持权限管理，确保客户只能查看自己项目内已发布的版本

## 二、规则与未知

### 已知规则
1. 身份管理：需要登录系统，支持电脑和手机网页访问
2. 项目管理：每个项目有指定的客户确认人
3. 版本管理：支持多版本管理，每个版本都有时间戳
4. 审核流程：审核通过自动发布，旧版本只读
5. 意见处理：必须先处理意见才能确认
6. 确认流程：客户确认后需要修改时，需提交重新修改申请
7. 权限控制：客户只能查看自己项目内已发布的版本
8. 文件管理：支持图片和PDF文件，允许下载
9. 意见关联：修改意见必须关联具体设计稿及版本
10. 历史保留：旧版本与旧意见保留，旧版本的确认不能直接算作新版本已确认

### 未知问题
1. 项目成员的确认机制
2. 项目创建和成员加入的流程
3. 项目删除和成员移除的权限管理
4. 文件存储方案和访问控制
5. 项目邀请机制和访问链接生成
6. 项目数据备份和恢复机制
7. 系统安全机制和数据加密
8. 系统性能和文件存储限制
9. 项目版本更新的触发机制
10. 系统通知和提醒机制（虽然用户明确表示不做微信自动通知）

## 三、关键状态及权限

| 状态 | 操作 | 权限 |
|------|------|------|
| 项目创建 | 只能由项目负责人创建 | 项目负责人 |
| 项目加入 | 可通过链接加入 | 项目成员 |
| 设计稿上传 | 只能由设计师上传 | 设计师 |
| 设计稿审核 | 只能由项目负责人审核 | 项目负责人 |
| 设计稿发布 | 审核通过后自动发布 | 系统自动 |
| 意见提交 | 客户可提交意见 | 客户 |
| 意见处理 | 项目负责人处理意见 | 项目负责人 |
| 确认操作 | 客户确认设计稿 | 客户确认人 |
| 版本更新 | 可创建新版本 | 项目负责人 |
| 版本删除 | 不允许删除已发布版本 | 系统限制 |
| 文件下载 | 允许下载已发布的版本 | 所有用户 |
| 文件撤销 | 撤销访问不影响已下载副本 | 系统自动 |

## 四、数据与接口

### 数据模型

1. 项目表 (Project)
   - 项目ID (PK)
   - 项目名称
   - 项目负责人ID
   - 客户确认人ID
   - 创建时间
   - 状态 (活跃/归档)

2. 用户表 (User)
   - 用户ID (PK)
   - 用户名
   - 电子邮箱
   - 身份 (设计师/项目负责人/客户)
   - 项目ID (FK)

3. 设计稿表 (Design)
   - 设计稿ID (PK)
   - 项目ID (FK)
   - 上传人ID (FK)
   - 文件名
   - 文件类型 (图片/PDF)
   - 上传时间
   - 版本号
   - 状态 (草稿/已审核/已发布)

4. 意见表 (Comment)
   - 意见ID (PK)
   - 设计稿ID (FK)
   - 提交人ID (FK)
   - 内容
   - 页码 (PDF专用)
   - 提交时间
   - 状态 (待处理/已处理)

5. 确认记录表 (Confirmation)
   - 确认ID (PK)
   - 设计稿ID (FK)
   - 确认人ID (FK)
   - 确认时间
   - 确认状态 (确认/未确认)

### 接口设计

1. 项目管理接口
   - 创建项目 (POST /projects)
   - 获取项目列表 (GET /projects)
   - 获取项目详情 (GET /projects/{id})

2. 用户管理接口
   - 获取用户信息 (GET /users/{id})
   - 获取用户项目列表 (GET /users/{id}/projects)

3. 设计稿管理接口
   - 上传设计稿 (POST /designs)
   - 获取设计稿列表 (GET /designs)
   - 获取设计稿详情 (GET /designs/{id})
   - 审核设计稿 (PUT /designs/{id}/review)
   - 发布设计稿 (PUT /designs/{id}/publish)

4. 意见管理接口
   - 提交意见 (POST /comments)
   - 获取意见列表 (GET /comments)
   - 获取特定设计稿意见 (GET /designs/{id}/comments)
   - 处理意见 (PUT /comments/{id}/process)

5. 确认管理接口
   - 确认设计稿 (POST /confirmations)
   - 获取确认记录 (GET /confirmations)
   - 获取特定设计稿确认记录 (GET /designs/{id}/confirmations)
