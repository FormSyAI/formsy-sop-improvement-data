# 产品 SOP：对话式数据分析工具——历史问题修改与删除

版本：草案 v0.1（未确认）。本文档为产品行为设计与制作计划，不涉及代码实现，不表示任何功能已开发、测试或上线。

---

## 0. 事实 / 建议 / 未知 分类声明

| 类别 | 内容 |
| --- | --- |
| **已明确（来自需求方）** | ① 工具形态：上传销售数据后可连续自然语言提问，Agent 分析并可画图；② 新增能力：修改历史问题、删除历史问题；③ 修改后须结合之前对话重新回答；④ 删除时须删除该问题及其后续回答，并更新对话历史。 |
| **建议（本文档提出，待需求方确认）** | 编辑入口位置、分支截断策略、图表联动规则、撤销窗口、权限分级、状态命名等所有具体设计选择，下文以“建议”标注。 |
| **未知（需需求方补充决定）** | 见 §8，共 9 项关键待决问题。 |

## 1. 用户与问题

- **使用者**：数据分析人员 / 业务人员（单人使用为主；是否存在多用户共享同一会话未提供——未知 U1）。
- **当前困难**：提问写错地区、指标或时间范围后，错误问题仍留在历史中，污染后续回答的上下文，且无法回退。
- **目标结果**：用户能修正或移除历史问题，使对话历史与 Agent 实际使用的上下文保持一致，后续回答基于修正后的历史。

## 2. 范围

**首版范围内**：修改历史问题、删除历史问题、重新回答、图表联动更新、对话历史更新、（建议）删除撤销。

**范围外（建议，待确认）**：批量删除、问题重排序、会话级回滚、多用户协作编辑、修改 Agent 回答本身。

## 3. 用户可以在哪些位置做什么（建议）

| 位置 | 可做动作 | 说明 |
| --- | --- | --- |
| 每条用户问题气泡上（悬停/长按/右键菜单） | 修改、删除 | 建议入口：问题气泡右上角“⋯”菜单，含“修改问题”“删除此问题及之后” |
| 修改模式（内联编辑框） | 编辑文本、确认、取消 | 确认前展示影响提示（见 §4.1） |
| 删除确认弹层 | 确认删除、取消、（建议）撤销 | 删除为级联删除，须二次确认 |
| 会话顶部/历史面板 | 查看当前生效的对话历史 | 只读 |

**建议**：回答气泡和图表卡片本身不提供独立编辑/删除入口，避免历史中回答与来源问题脱钩。

## 4. 修改或删除后，问题、回答、图表怎样变化

### 4.1 修改问题（建议方案）

1. 用户进入编辑，改写问题文本（例：把“华东”改为“华南”）。
2. 确认前提示：“将重新生成此问题及之后 N 条回答”（N = 该问题之后的问答轮数）。
3. 确认后：
   - 该问题文本更新为新版本（建议保留原文本于版本记录，见 §5）；
   - 该问题的旧回答标记为“已失效”（建议：折叠灰显而非立即物理删除，可展开查看）；
   - 该问题之后的所有问答轮**截断**：旧回答失效，Agent 基于修改前的问题序列 + 新问题重新回答；
   - 该问题之后用户是否需要重新逐条提问：**建议**首版不自动重放后续问题（后续问题可能依赖旧语境），只重新回答被修改的这一条，后续由用户自行决定是否重问。⚠️ 此点与“结合之前的对话重新回答”存在解释空间，列为待决 U2。
4. 图表：由被截断回答生成的图表一并失效；新回答若含图表则生成新图。旧图建议随旧回答归档灰显，不自动删除文件（待决 U3：旧图表是否可追溯查看）。

### 4.2 删除问题

1. 用户点击删除，确认弹层列出将删除的范围：“此问题、其回答，及其后 N 轮问答”。
2. 确认后：该问题及其回答、其后所有问答轮从生效历史中移除；关联图表从界面移除。
3. **建议**：提供有限时撤销（如 10 秒内可恢复），是否需要待决（U4）。
4. Agent 后续提问的上下文 = 删除后剩余的历史。

### 4.3 上下文一致性规则（核心不变量）

- **单一事实源**：存在一份“生效对话历史”，Agent 每次回答只读取该历史；界面展示与该历史一致。
- 修改/删除是**对该历史的原子操作**：操作完成前 Agent 不基于中间状态回答；操作期间建议锁定输入框或排队新提问（待决 U5）。
- 失效/删除的回答不再进入 Agent 上下文；图表引用的回答失效则图表标记失效。

## 5. 状态设计

### 5.1 问答轮状态（建议）

| 状态 | 含义 | 进入 | 退出 |
| --- | --- | --- | --- |
| `active` | 生效中，参与上下文 | 新回答完成 | 被修改/删除触发 `stale`/移除 |
| `generating` | Agent 回答生成中 | 提问/重新回答提交 | 完成→`active`；失败→`failed` |
| `stale`（失效） | 因上游修改/删除不再生效，灰显可展开 | 上游问题被修改 | 用户重问生成新 `active` 轮 |
| `failed` | 生成失败 | 生成出错 | 重试→`generating` |
| `deleted`（含撤销窗口 `pending_delete`） | 已从生效历史移除 | 删除确认 | 撤销窗口内恢复→`active` |

### 5.2 关键状态迁移

| 当前状态 | 事件 | 下一状态 | 数据/副作用 | 可见结果 |
| --- | --- | --- | --- | --- |
| `active`（问题 i） | 用户确认修改 | 问题文本更新；轮 i 回答→`stale`；轮 i 之后全部→`stale` | 新一轮 `generating` | 编辑框关闭，重新生成中 |
| `active`（问题 i） | 用户确认删除 | 轮 i 及之后→`pending_delete` | 从生效历史移除 | 界面移除 + 撤销提示 |
| `pending_delete` | 撤销窗口过期 | `deleted` | 不可恢复（或归档，待决） | 无 |
| `generating` | 生成失败 | `failed` | 历史不变 | 错误提示 + 重试 |
| 用户修改问题 i 时，轮 j>i 正在 `generating` | 冲突 | **待决 U5**：建议取消轮 j 生成并标 `stale` | — | 提示被取消 |

## 6. 角色、权限与数据

- **建议**：首版单用户会话，会话创建者拥有全部操作权限（提问、修改、删除自己的问题）；无角色区分。
- 若存在共享会话（未知 U1）：建议只有会话所有者可修改/删除，其他成员只读——待需求方确认。
- **数据副作用**：修改/删除会改变生效历史；建议保留操作审计记录（谁、何时、改了什么、原文本），原问题文本保留在版本记录中用于追溯——是否保留、保留多久待决（U6，涉及数据保留政策）。
- 无收费、无外部数据外发新增副作用（Agent 调用按既有机制，不在本次范围）。

## 7. 正常路径、异常路径与验收

### 7.1 正常路径

| 路径 | 步骤 | 可验收断言 |
| --- | --- | --- |
| 修改并重新回答 | 上传数据→问 Q1（华东）→问 Q2→修改 Q1 为“华南”→确认 | ① Q1 文本已更新；② Q1 旧回答灰显失效；③ Q2 轮失效；④ 新回答基于“华南”生成且内容与华南数据一致；⑤ 后续新提问的上下文不含失效轮 |
| 删除 | 问 Q1、Q2、Q3→删除 Q2→确认 | ① Q2、Q3 及其回答、图表从界面移除；② 后续提问回答不引用 Q2/Q3 内容；③ Q1 仍正常 |
| 图表联动 | Q3 要求画图→修改 Q2 | Q3 图表失效灰显；重新生成后新图对应新数据 |

### 7.2 异常路径

| 异常 | 建议行为 | 验收断言 |
| --- | --- | --- |
| 修改后重新生成失败 | 历史保持修改后状态，该轮 `failed`，提供重试；不自动回滚问题文本 | 重试入口可用；重试成功后回答与修改后问题一致 |
| 生成进行中用户发起修改/删除 | 提示冲突；建议取消进行中生成（U5 待决） | 无基于旧上下文的回答混入新历史 |
| 删除时撤销窗口内用户发新提问 | 允许；新提问基于删除后历史 | 新回答不引用已删内容 |
| 编辑后问题为空/超长 | 前端校验，禁止提交 | 无空问题进入历史 |
| 操作时网络/服务中断 | 操作未确认则历史不变，提示失败 | 历史无中间态（无“半删除”状态） |
| 修改首条问题 | 同一般规则（首条之前无历史） | 正常重新回答 |

### 7.3 验收环境与证据计划（设计，未执行）

- 环境：目标平台 + 示例销售数据集。
- 每条断言配操作录屏/截图 + Agent 回答文本核对（如修改“华东→华南”后，回答中的数字应等于华南数据）。
- 上下文一致性验收：删除 Q2 后追问“刚才第二个问题的结论是什么”，Agent 应回答当前生效历史的第二问，而非已删问题——此验收口径需需求方确认（U7）。

## 10. 基础自查结论（PC 摘要）

- PC01/PC02/PC03：用户问题与目标来自需求方原文，明确；范围建议部分待确认——**满足（草案级）**。
- PC05 完整旅程：修改/删除主路径完整；并发冲突分支依赖 U5——**部分满足，待决**。
- PC08 状态与规则：状态机内部一致，但“修改后是否重放后续问题”两种解释并存——**不满足直至 U2 决定**。
- PC09 异常：已列主要异常；生成中断恢复细节属技术承接——**满足（草案级）**。
- PC10 数据/权限：单用户下满足；共享会话场景未核查（U1）。
- PC12 验收：断言可判定，未执行——**设计满足，实际验收未执行**。
- PC13 追踪：每条需求（修改、删除、上下文一致）均有对应功能与验收——**满足**。

**结论**：草案可交付评审；U1–U9 中 U2、U5、U7 为实施前必须决定项，其余可带条件推进。本文档所有“建议”均未经需求方确认，不构成已批准决定。
