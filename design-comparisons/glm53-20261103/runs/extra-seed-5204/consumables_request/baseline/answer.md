# 工作室耗材领用系统 · 产品 SOP 与实施前计划

---

## 一、范围界定

### 1.1 目标
建立一套从“员工按项目申请耗材 → 负责人审批 → 仓库确认库存并发放 → 领用人签收”的闭环领用流程，支持部分发放，全程留痕可追溯。

### 1.2 范围内（In Scope）
- 耗材申请单的创建、提交、撤回
- 按项目维度关联领用（一个申请单归属一个项目）
- 负责人审批（通过 / 驳回 / 部分批准）
- 仓库库存校验、发放执行（支持部分发放、分批发放）
- 领用人签收确认
- 全流程操作日志与状态留痕

### 1.3 范围外（Out of Scope）
- 耗材采购、入库、供应商管理（仅读取库存数据）
- 项目立项与预算管理（仅关联项目编号）
- 耗材成本核算与财务报销
- 耗材归还流程（如需，列入待确认）

## 二、角色与权限

| 角色 | 权限 | 说明 |
|---|---|---|
| 普通员工（申请人/领用人） | 创建/编辑/提交/撤回自己的申请单；查看自己单据状态；签收 | 仅本人单据 |
| 项目负责人 | 审批本项目申请单（通过/驳回/调整数量）；查看本项目全部单据 | 按项目归属授权 |
| 仓库管理员 | 库存校验、执行发放（整单/部分）、登记实发数量；查看待发放单据 | 可多人，需记录操作人 |
| 工作室管理员 | 查看全部单据与统计；配置耗材目录、审批人映射；处理异常单 | 后台管理 |
| 系统 | 自动校验库存、自动流转状态、超时提醒 | 自动化规则 |

**权限原则**：申请人与审批人不可为同一人；仓库发放人与申请人分离（签收环节由领用人本人完成）。

## 三、完整流程

### 3.1 主流程

```
① 员工创建申请单
   └─ 选择项目 → 添加耗材明细（名称/规格/数量/用途备注）→ 提交
② 负责人审批
   ├─ 通过 → 进入「待发放」
   ├─ 部分批准（调整数量）→ 进入「待发放」（按批准数量）
   └─ 驳回（填写原因）→ 终止，员工可修改后重新提交
③ 仓库确认库存
   ├─ 库存充足 → 执行发放 → 进入「待签收」
   ├─ 库存不足 → 部分发放（登记实发数量）→ 进入「待签收」
   └─ 完全无货 → 标记「缺货待补」，可等待补货或员工撤回
④ 领用人签收
   ├─ 确认实发数量无误 → 签收 → 单据「已完成」
   └─ 数量/品类不符 → 拒签并说明 → 退回仓库处理
⑤ 库存扣减与留痕归档
```

### 3.2 关键规则
- **部分发放**：仓库按实际可发数量发放，剩余数量标记为「未发放」；员工可选择“放弃剩余”或“保留待补”，保留部分在补货后可继续发放（分批发放，每批独立签收）。
- **撤回**：仅「待审批」状态可撤回；「待发放」状态撤回需负责人同意。
- **修改重提**：驳回后员工修改重新提交，重新进入审批。
- **超时提醒**（建议值，待确认）：待审批超 24h、待签收超 48h 系统提醒。

## 四、状态定义与异常处理

### 4.1 单据状态机

| 状态 | 触发动作 | 后续可达状态 |
|---|---|---|
| 草稿 | 创建未提交 | 待审批 / 作废 |
| 待审批 | 提交 | 待发放 / 已驳回 / 已撤回 |
| 已驳回 | 负责人驳回 | 草稿（修改重提）/ 关闭 |
| 待发放 | 审批通过 | 待签收 / 缺货待补 |
| 缺货待补 | 库存不足且员工选择等待 | 待发放（补货后）/ 已关闭 |
| 待签收 | 仓库发放 | 已完成 / 发放异常 |
| 发放异常 | 领用人拒签 | 待发放（仓库重新处理）/ 已关闭 |
| 已完成 | 领用人签收 | 终态 |
| 已关闭 | 撤回/放弃剩余/作废 | 终态 |

### 4.2 异常场景

| 异常 | 处理方式 |
|---|---|
| 库存不足 | 部分发放或转「缺货待补」 |
| 审批人离职/未配置 | 升级至工作室管理员代审，并告警 |
| 领用人拒签 | 单据退回仓库，需仓库说明并重新发放或关闭 |
| 发放后库存出现负数（并发） | 发放时锁定库存额度，签收后正式扣减；异常时冻结单据并人工核查 |
| 员工离职有未完成单 | 管理员批量关闭或转移领用人 |
| 重复申请/异常大量领用 | 管理员可标记审查，暂缓发放 |

## 五、数据与留痕

### 5.1 核心数据对象
- **申请单**：单号、申请人、项目、用途说明、状态、创建/提交时间
- **申请明细**：耗材编码、名称规格、申请数量、批准数量、实发数量、未发数量
- **发放记录**：发放批次、实发明细、发放人、发放时间
- **签收记录**：签收人、签收时间、签收方式、拒签原因（如有）
- **操作日志**：每次状态变更的操作人、时间、动作、备注（不可删除）

### 5.2 留痕要求
- 所有状态变更必须记录操作人 + 时间戳 + 前后状态
- 审批意见、驳回原因、拒签原因均为必填文本
- 单据完成后不可物理删除，仅可归档；数据保留期限 ≥ 2 年（待确认）
- 支持按项目/人员/耗材/时间段导出领用报表

## 六、验收标准

1. **流程闭环**：从提交到签收全链路可走通，每一步状态流转正确、日志完整。
2. **部分发放**：库存不足时能正确登记实发数量，剩余数量可继续分批发放并独立签收。
3. **权限隔离**：员工仅见自己单据；负责人仅审本项目；仓库不能审批；审批人不能审自己的申请。
4. **留痕完整**：任意单据可回溯完整操作历史，含驳回/拒签原因。
5. **异常覆盖**：缺货、拒签、审批人缺失、并发发放等场景均有明确处理路径。
6. **报表可用**：可按项目维度统计耗材消耗。

## 八、事实与建议区分

**事实（来自需求）**：员工按项目提交耗材和数量；负责人审批；仓库确认库存并发放；允许部分发放；领用人签收。

**建议（设计决策，需评审确认）**：驳回后修改重提机制、缺货待补状态、分批发放独立签收、审批人与申请人分离、库存锁定机制、超时提醒时限、报表导出能力。

建议在开发前先确认第七节全部事项，并组织一次流程评审会签后再进入原型设计阶段。
