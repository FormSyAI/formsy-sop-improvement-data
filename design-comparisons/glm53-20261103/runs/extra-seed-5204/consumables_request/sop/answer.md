## 4. 完整用户旅程与流程

### 主流程（正常路径）

1. **提交**：员工选择项目 → 添加耗材条目（耗材 + 数量）→ 提交申请。系统校验必填项，生成申请单号。
2. **审批**：负责人收到待审批申请 → 通过 或 驳回（可填驳回原因，建议必填）。
3. **库存确认与发放**：仓库查看已通过申请 → 逐项核对库存 → 选择全额发放或部分发放（每项耗材填写实发数量）→ 确认发放。
4. **签收**：领用人查看发放结果 → 确认签收（建议支持备注差异）。
5. **完成**：申请单进入“已完成”，全程记录可查。

### 状态机

| 状态 | 进入条件 | 可迁移到 |
| --- | --- | --- |
| 草稿 | 员工创建未提交 | 已提交、已撤回（删除） |
| 待审批 | 员工提交 | 已通过、已驳回 |
| 已驳回 | 负责人驳回 | 已关闭（员工确认）/ 员工修改后重新提交（建议，待确认） |
| 待发放 | 负责人通过 | 部分发放中、已发放 |
| 部分发放中 | 仓库首次部分发放，尚有未发项 | 已发放（补发完成）、已关闭（终止剩余） |
| 已发放 | 全部实发完成 | 已签收 |
| 已签收 | 领用人确认 | 已完成（终态） |
| 已撤回/已关闭 | 员工撤回 / 终止 | 终态 |

### 异常与边界（建议设计，覆盖适用风险）

| 场景 | 产品行为 |
| --- | --- |
| 审批前撤回 | 员工可撤回，单据关闭留痕 |
| 审批后撤回 | 不允许直接撤回；需负责人驳回或仓库终止（规则待确认） |
| 库存不足 | 仓库可部分发放；剩余项状态明确（待补发/终止），不静默丢弃 |
| 驳回后重提 | 建议允许修改重提，保留历史版本记录（待确认） |
| 重复提交 | 同一员工同一项目重复申请允许（耗材可多次领用），系统提示但不阻止（待确认） |
| 签收争议 | 领用人可备注差异；差异处理流程待确认 |
| 仓库发放后库存为负/并发发放 | 并发库存扣减规则属技术待承接项（H1） |
| 负责人长期未审批 | 提醒/超时规则待确认（建议首版仅展示待办，不做自动流转） |

## 5. 数据与留痕

**核心数据对象（建议）**：
- 申请单：单号、申请人、项目、状态、创建/提交时间、条目列表
- 申请条目：耗材、申请数量、实发数量、条目状态
- 操作记录：每次状态变更的操作人、时间、动作、备注（驳回原因、部分发放说明、签收备注）

**留痕要求（建议，待确认）**：
- 所有状态变更不可物理删除，撤回/关闭保留记录
- 部分发放须记录每次发放的明细与时间
- 是否需要导出/报表、保留期限、删除规则：待确认

## 6. 验收设计（草案）

| 验收 ID | 场景 | 断言 |
| --- | --- | --- |
| AC01 | 员工提交含项目与耗材的申请 | 生成单号，状态=待审批，负责人可见 |
| AC02 | 负责人通过 | 状态=待发放，仓库可见 |
| AC03 | 负责人驳回（含原因） | 状态=已驳回，员工可见原因 |
| AC04 | 库存不足，仓库部分发放 | 条目实发数<申请数，单据=部分发放中，剩余项状态明确 |
| AC05 | 补发完成 | 单据=已发放 |
| AC06 | 领用人签收 | 状态=已签收→已完成，操作记录完整 |
| AC07 | 查看任一完成单据 | 可追溯每次操作人/时间/动作 |

验收环境、数据与执行方式待技术承接后细化。
