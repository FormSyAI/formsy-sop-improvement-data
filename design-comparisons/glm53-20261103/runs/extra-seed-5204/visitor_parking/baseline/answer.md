# 办公园区访客停车预约项目 · 产品SOP与实施前计划

---

## 一、项目范围

### 1.1 目标
为办公园区提供访客停车全流程线上化管理：访客在线提交停车预约 → 被访人确认 → 物业审核车位 → 到场核验入场 → 离场记录归档，实现预约可查、入场可控、留痕可溯。

### 1.2 范围内
- 访客预约提交（姓名、车牌、来访时间、被访人）
- 被访人确认/拒绝
- 物业查看预约与车位余量、审核分配
- 入场核验（车牌识别/人工核验）
- 离场记录与数据归档
- 预约状态流转与异常处理

### 1.3 范围外（本期不做）
- 停车费计算与在线支付（如需收费，仅记录时长供线下结算）
- 长租车位、员工固定车位管理
- 访客门禁/楼宇通行联动
- 多园区统一管理（本期单园区）

---

## 二、角色与权限

| 角色 | 权限 |
|---|---|
| **访客** | 提交/修改/取消本人预约；查看本人预约状态 |
| **被访人（员工）** | 查看、确认/拒绝关联预约；可代访客取消 |
| **物业运营员** | 查看全部预约与车位余量；审核分配车位；核验入场/离场；处理异常 |
| **物业管理员** | 运营员全部权限 + 车位池配置、数据导出、操作日志查看 |
| **系统管理员** | 账号与角色管理、系统配置 |

> 权限原则：数据最小可见——被访人只见本人相关预约，访客仅见本人预约。

## 三、完整流程（主流程）

```
访客提交 → 被访人确认 → 物业审核分配 → 到场核验入场 → 离场记录 → 归档
```

### 阶段1：预约提交
1. 访客通过预约入口（链接/小程序，由被访人转发）填写：姓名、车牌、来访时间（日期+时段）、被访人、联系方式（建议补充）。
2. 系统校验：车牌格式、时间是否在可预约范围内（建议：最早提前1天，最晚提前2小时，具体待确认）、该时段车位余量是否>0。
3. 校验通过 → 状态置为 **待确认**，通知被访人。

### 阶段2：被访人确认
4. 被访人在时限内（建议：来访前12小时，超时自动提醒，具体待确认）确认或拒绝。
5. 确认 → **待物业审核**，通知物业；拒绝 → **已拒绝**，通知访客。

### 阶段3：物业审核
6. 物业查看预约详情与目标时段车位余量。
7. 通过 → 分配车位（系统自动或人工指定），状态 **已预约**，通知访客（含入场凭证/二维码）。
8. 车位不足或信息异常 → **物业驳回**，注明原因，通知访客与被访人。

### 阶段4：入场
9. 访客到场，道闸车牌识别匹配或人工扫码核验。
10. 匹配成功且在预约时段内 → 放行，状态 **已入场**，记录入场时间。
11. 不匹配/超时段 → 转异常处理（见第五节）。

### 阶段5：离场与归档
12. 车辆离场，道闸识别或人工确认，记录离场时间。
13. 状态 **已完成**，数据归档，释放车位占用。

## 四、状态定义

| 状态 | 说明 |
|---|---|
| 待确认 | 访客已提交，等被访人确认 |
| 待物业审核 | 被访人已确认，等物业审核 |
| 已预约 | 物业通过并分配车位，生效中 |
| 已入场 | 核验通过，车辆在场 |
| 已完成 | 离场记录完成，归档 |
| 已取消 | 访客/被访人主动取消 |
| 已拒绝 | 被访人拒绝 |
| 物业驳回 | 物业审核不通过 |
| 已过期 | 到预约时段结束仍未入场，自动失效 |
| 异常 | 入场核验失败、超时未离场等，需人工介入 |

---

## 五、异常处理

| 异常场景 | 处理方式 | 状态 |
|---|---|---|
| 被访人超时未确认 | 系统提醒；再超时（建议24h）自动取消并通知双方 | 已取消 |
| 车牌与预约不符 | 入口人工核验：核实身份后可现场修改车牌（需物业权限+留痕）或拒绝入场 | 异常→已入场/物业驳回 |
| 提前到场（早于预约时段） | 建议允许±30分钟弹性（待确认）；超出则人工判断放行或改约 | 异常 |
| 超时未入场 | 预约时段结束后自动释放车位 | 已过期 |
| 超时未离场 | 系统提醒被访人与物业；物业跟进；是否收费/拉黑待确认 | 异常 |
| 访客临时取消 | 入场前可取消，自动释放车位 | 已取消 |
| 车位临时被占 | 物业改派车位并通知访客 | 已预约（更新车位） |
| 预约信息填错 | 入场前访客可修改（重新触发确认流程）或取消重提 | 回到待确认 |
| 系统故障无法核验 | 人工登记放行，事后补录 | 异常→已入场 |

## 六、数据与留痕

### 6.1 核心数据实体
- **预约单**：预约编号、访客姓名、联系方式、车牌、来访时间、被访人、状态、车位号、创建/更新时间
- **出入记录**：入场时间、入场方式（识别/人工）、核验人、离场时间、离场方式
- **车位池**：总车位、时段占用、余量
- **操作日志**：所有状态变更的操作人、时间、动作、原因（驳回/修改必填原因）

### 6.2 留痕要求
- 每次状态变更记录：操作者、时间、前后状态、备注。
- 车牌修改、人工放行、异常处理必须留痕且不可删除。
- 数据保留期限建议≥1年（待确认，需符合园区安保合规要求）。
- 敏感信息（车牌、手机号）按最小可见原则展示，导出需物业管理员权限。

## 七、验收标准

1. **主流程贯通**：访客提交→确认→审核→入场→离场全链路状态流转正确，各节点通知及时送达。
2. **权限验证**：各角色仅能访问授权数据；越权操作被拒绝。
3. **状态一致性**：车位余量与预约状态实时一致；取消/过期后车位正确释放。
4. **异常覆盖**：上述9类异常场景均有明确处理路径与留痕。
5. **核验准确**：车牌识别匹配入场成功率达标（建议≥95%，待确认）；人工核验通道可用。
6. **数据完整**：所有预约与出入记录可查询、可导出，日志不可篡改。
7. **性能**：核验入场响应时间≤3秒（待确认）。

## 八、待确认事项（实施前需与相关方确认）

| # | 事项 | 涉及方 |
|---|---|---|
| 1 | 预约提前量规则（最早/最晚提前多久） | 物业、园区管理方 |

| 7 | 访客入口形态：小程序/H5/公众号，是否需实名 | IT、园区管理方 |
| 8 | 数据保留期限与隐私合规要求（个人信息保护） | 法务、园区管理方 |
| 9 | 是否需要黑名单（车牌/人员）机制 | 安保 |
| 10 | 单访客/单被访人预约数量上限、同车牌重复预约限制 | 产品 |

## 九、事实与建议区分

**事实（需求已明确）**：四类角色、五步主流程、核心字段（姓名、车牌、来访时间、被访人）、核验入场与离场记录。

**建议（需确认后生效）**：各处时限参数、弹性入场规则、通知机制、异常处理细则、数据保留期限、验收指标数值。以上建议均已在第八节列为待确认项，确认后纳入正式SOP基线。
