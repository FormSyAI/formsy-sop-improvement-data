## 2. 范围与优先级

**首版范围内（事实）**
1. 访客提交预约：姓名、车牌、来访时间、被访人
2. 被访人确认
3. 物业查看预约列表与车位余量
4. 到场核验入场
5. 离场完成记录

**范围外（建议，待确认）**
- 车位级分配（指定具体车位号）
- 访客自助取消/改期
- 停车计费
- 黑名单管理、长期访客白名单
- 多园区/多门岗

## 3. 角色与权限

| 角色 | 权限 | 数据可见范围 |
| --- | --- | --- |
| 访客 | 创建预约、查看本人预约状态 | 仅本人预约 |
| 被访人 | 确认/拒绝与本人相关的预约 | 与自己相关的预约信息 |
| 物业 | 查看全部预约、车位余量、执行核验入场/离场记录 | 全部预约与出入记录 |
| 系统管理员 | 账号与配置（建议，待确认是否需要） | — |

**权限原则（建议）**：访客不能看到其他访客信息；被访人不能代替物业核验入场；物业不能修改访客提交的车牌原文（如需纠错走异常流程，见 §6）。

## 4. 完整用户旅程与功能行为

### 4.1 旅程总览

```
访客提交 → 被访人确认 → 物业预览/余量查看 → 到场核验入场 → 离场记录
```

### 4.2 功能卡

**FR-01 访客提交预约**
- 触发：访客进入预约入口
- 输入：姓名（必填文本）、车牌（必填，格式校验规则待确认 Q2）、来访时间（必填，日期+时段）、被访人（必填，从园区人员中选择或输入姓名/工号——方式待确认 Q3）
- 正常输出：生成预约记录，状态=待确认；向被访人发出通知（通知渠道待确认 Q4）
- 副作用：写入一条预约数据
- 完成判据：访客看到“已提交，等待确认”及预约编号

**FR-02 被访人确认**
- 前置：存在状态=待确认且被访人为本人的预约
- 动作：确认 / 拒绝（拒绝时是否要求填原因：待确认 Q5）
- 输出：状态→已确认 / 已拒绝；通知访客
- 异常：超时未确认（超时时长与到期后状态待确认 Q6）

**FR-03 物业查看预约与余量**
- 输入：日期/时段筛选
- 输出：预约列表（含状态）、对应时段车位余量
- 余量口径：按“已确认预约数 vs 总车位”计算（建议；是否分时段动态计算待确认 Q7）

**FR-04 到场核验入场**
- 前置：预约状态=已确认且在来访时间窗口内（窗口宽度待确认 Q8）
- 动作：物业核对车牌/姓名与预约一致 → 标记入场
- 输出：状态→已入场，记录入场时间
- 异常：见 §6 E1–E4

**FR-05 离场记录**
- 动作：物业对已入场车辆标记离场
- 输出：状态=已完成，记录离场时间
- 完成判据：形成完整出入留痕记录

## 5. 业务状态

```
待确认 → 已确认 → 已入场 → 已完成
   ↓        ↓
 已拒绝   已取消/已过期
```

| 状态 | 进入条件 | 允许动作 | 退出 |
| --- | --- | --- | --- |
| 待确认 | 访客提交 | 被访人确认/拒绝；访客取消（若授权） | 已确认/已拒绝/已取消 |
| 已确认 | 被访人确认 | 核验入场；取消 | 已入场/已取消/已过期 |
| 已入场 | 物业核验通过 | 离场记录 | 已完成 |
| 已完成 | 离场 | 只读 | 终态 |
| 已拒绝/已取消/已过期 | 见异常 | 只读 | 终态 |

**规则**：只有“已确认”可入场；未确认预约到场按异常 E2 处理；已过期不可入场（是否允许物业人工放行并补登记：待确认 Q9）。

## 6. 异常与边界

| ID | 场景 | 产品行为（建议） |
| --- | --- | --- |
| E1 | 车牌与预约不符 | 物业拒绝入场，提示原因；不改原预约 |
| E2 | 到场但预约未确认 | 提示联系被访人；被访人可现场确认后入场 |
| E3 | 时段车位已满仍提交 | 允许提交但提示余量紧张，或阻止提交（待确认 Q10） |
| E4 | 访客未到场 | 到时段结束自动转已过期 |
| E5 | 超时未离场 | 记录仍在场；是否提醒/计费在范围外 |
| E6 | 重复提交同车牌同时段 | 识别重复，提示已有预约 |
| E7 | 被访人离职/填错 | 拒绝或转人工处理（待确认 Q11） |
| E8 | 访客提前/迟到到场 | 在窗口内（Q8）正常入场；窗口外按 E2 类逻辑 |

## 7. 数据与留痕

| 数据 | 字段 | 所有者 | 保留 |
| --- | --- | --- | --- |
| 预约记录 | 预约编号、姓名、车牌、来访时间、被访人、状态、各状态时间戳、操作人 | 系统 | 建议保留期待确认 Q12 |
| 出入记录 | 入场时间/操作物业、离场时间/操作物业、关联预约编号 | 系统 | 同上 |

**留痕要求**：每次状态变更记录操作者、时间、前后状态；已完成记录不可删除（建议）。个人信息（姓名、车牌）属敏感数据，访问范围按 §3 权限表；是否需要脱敏展示给物业以外角色待确认。

## 8. 验收设计（草案）

| SC ID | 场景 | 断言 |
| --- | --- | --- |
| SC-01 | 访客填写完整信息提交 | 生成预约编号，被访人收到通知，状态=待确认 |
| SC-02 | 被访人确认 | 状态=已确认，访客可见 |
| SC-03 | 物业查看当日列表 | 已确认预约与余量显示正确 |
| SC-04 | 匹配车辆核验入场 | 状态=已入场，入场时间留痕 |
| SC-05 | 离场记录 | 状态=已完成，出入时间完整 |
| SC-06 | 车牌不符（E1） | 拒绝入场，预约状态不变，有提示 |
| SC-07 | 未确认到场（E2） | 不允许直接入场，有引导 |
| SC-08 | 重复提交（E6） | 系统识别并提示 |

验收环境、平台与执行方式待平台确定后补充；当前为设计，未执行。
