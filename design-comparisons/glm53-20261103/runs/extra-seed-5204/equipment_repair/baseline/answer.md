# 实验室设备维修管理 SOP（产品视角）

---

## 一、文档说明

- **事实**（需求已明确）：报修由使用人发起、需填写影响程度；维修人员接单、诊断、维修或转外修；完成后使用人验收；维修期间设备不可预约。
- **建议**（设计补充）：以下标注【建议】的内容为产品方案建议，需与业务方确认后固化。

---

## 二、范围界定

### 2.1 范围内
- 设备故障报修工单全生命周期：报修 → 接单 → 诊断 → 维修/外修 → 验收 → 关闭
- 维修期间设备预约状态联动（锁定/恢复）
- 维修记录留痕与查询

### 2.2 范围外（需确认是否纳入后续版本）
- 设备采购、报废、调拨流程
- 预防性维护/保养计划（建议二期）
- 备品备件库存管理（建议二期）
- 维修费用结算与供应商对账（若外修涉及付款，需确认归属系统）

---

## 三、角色与权限

| 角色 | 核心权限 | 说明 |
|---|---|---|
| 使用人（报修人） | 提交报修、查看本人工单进度、验收/驳回验收 | 【建议】验收驳回需填写理由 |
| 维修人员 | 接单、诊断、填写维修记录、提交完成、发起外修申请 | 只能处理分配/认领给自己的工单 |
| 维修管理员（【建议】新增） | 工单分派/改派、外修审批、超时催办、强制关闭、数据导出 | 中大型实验室建议设置；小型场景可由维修人员兼任 |
| 设备管理员 | 设备台账维护、预约规则配置 | |
| 系统管理员 | 角色权限配置、字典维护 | |

**权限原则**：使用人不可查看维修内部诊断细节（【建议】可放开只读）；维修人员不可代替使用人验收；验收操作仅限报修人或设备责任人。

---

## 四、完整流程

### 4.1 主流程

```
使用人报修 → 待接单 → 维修人员接单 → 诊断中
→ 分支A：内部维修 → 维修中 → 待验收 → 使用人验收
       → 通过 → 已完成（设备恢复可预约）
       → 驳回 → 退回维修中
→ 分支B：转外修 → 外修审批 → 外修中 → 返厂登记 → 待验收 → 同上
```

### 4.2 流程节点说明

1. **报修**：使用人选择设备、填写故障描述、故障发生时间、影响程度（建议分级：轻微/影响使用/影响实验进度/影响安全）、上传照片/视频。
2. **接单**：维修人员认领或管理员派单；【建议】接单后 X 小时内需完成诊断，超时提醒。
3. **诊断**：填写故障原因、维修方案（内部维修/建议外修）、预计完成时间、所需备件。
4. **内部维修**：记录维修过程、更换部件、耗时；完成后提交，工单进入待验收。
5. **外修**：填写外修原因、供应商、预计周期、费用预估 → 管理员审批 → 设备出库登记 → 外修中 → 返厂登记（含验收说明）→ 待验收。
6. **验收**：使用人确认设备恢复正常 → 工单关闭，设备恢复可预约；驳回则退回维修中并附理由。

### 4.3 预约联动规则

- 工单进入「已接单」及之后状态 → 设备预约状态置为**维修锁定**，新预约被拦截，已有预约【建议】自动取消并通知预约人（需确认）。
- 工单验收通过关闭 → 解锁，恢复可预约。

## 五、状态定义与异常处理

### 5.1 工单状态

| 状态 | 触发条件 |
|---|---|
| 待接单 | 报修提交 |
| 已接单/诊断中 | 维修人员接单 |
| 维修中 | 诊断为内部维修 |
| 外修审批中 | 诊断建议外修 |
| 外修中 | 审批通过、设备出库 |
| 待验收 | 维修完成/外修返厂登记 |
| 已完成 | 验收通过 |
| 已取消 | 报修人撤单（仅限待接单阶段）|
| 已关闭（异常） | 管理员强制关闭，需填理由 |

### 5.2 异常场景

| 异常 | 处理规则 |
|---|---|
| 长时间无人接单 | 超时升级提醒管理员；【建议】超 24h 自动派单或短信催办 |
| 诊断超时 | 系统提醒维修人员及管理员 |
| 验收驳回 | 退回维修中，记录驳回理由，维修人员需重新处理 |
| 多次驳回（建议≥2次） | 升级管理员介入，可改派或转外修 |
| 外修超期未返 | 临近预计返厂日提醒；超期标记并通知管理员 |
| 重复报修同一设备 | 待接单阶段提示已有进行中工单，禁止重复提交 |
| 报修人离职/失联无法验收 | 【建议】超 3 天未验收自动通过或转设备管理员代验收（需确认） |
| 维修期间设备被误操作使用 | 线下管理问题，SOP 中明确设备须挂「维修中」标识牌 |

## 六、数据与留痕

### 6.1 核心数据对象
- **设备台账**：设备编号、名称、位置、状态（正常/维修锁定/外修/停用）
- **报修工单**：工单号、设备、报修人、故障描述、影响程度、附件、各环节时间戳
- **诊断记录**：故障原因、方案、预计耗时
- **维修记录**：过程描述、更换部件、维修人、实际耗时
- **外修记录**：供应商、费用、出库/返厂时间、审批链
- **验收记录**：验收人、结果、驳回理由、时间
- **操作日志**：所有状态变更、改派、强制关闭的操作人、时间、原因（不可篡改）

### 6.2 留痕要求
- 每次状态变更记录：操作人、时间、前后状态、备注。
- 附件（照片/视频）与工单绑定，作为故障与维修证据。
- 【建议】工单关闭后生成设备维修历史，支持按设备查询累计故障次数，为报废决策提供依据。

---

## 七、验收标准

- 使用人验收通过即工单完成；验收项【建议】：设备功能恢复正常、现场清理完毕、维修记录完整。
- SOP 上线验收标准：
  1. 全流程（含外修分支、驳回分支）可走通；
  2. 维修期间设备预约被正确拦截，关闭后正确恢复；
  3. 所有状态变更与操作留痕完整可查；
  4. 各角色权限边界经测试无越权；
  5. 异常场景（超时、驳回、重复报修）按规则触发提醒与流转。

## 八、待确认事项（未知项）

1. **是否设维修管理员角色**，还是由维修人员自行处理派单与外修审批？
2. **外修是否涉及费用审批**？审批层级与预算归属？
3. **维修期间已有预约如何处理**：自动取消还是人工通知后处理？
4. **验收超时机制**：使用人长期不验收，是否自动通过或转设备管理员？
5. **接单/诊断/维修的时效 SLA**：各环节超时时长阈值？
6. **影响程度分级标准**：是否需要与设备安全等级、实验排期联动（如影响安全的故障优先处理）？
7. **通知渠道**：站内信、短信、邮件，覆盖哪些节点？
8. **是否需要维修统计报表**（故障率、平均修复时长 MTTR、外修费用统计）？
9. **设备台账来源**：是否已有系统，还是本 SOP 内新建？
