# 企业培训作业系统 · 产品 SOP 与实施前计划

---

## 一、文档说明

- **文档性质**：产品流程规范（SOP）+ 实施前计划
- **适用对象**：产品、运营、讲师、学员、系统管理员、测试
- **事实与建议区分**：文中标注【事实】的为需求明确内容；标注【建议】的为设计补充，需评审确认。

---

## 二、项目范围

### 2.1 范围内【事实】
1. 讲师发布作业（含说明、附件、截止时间）
2. 学员上传文件提交作业
3. 截止时间前学员可多次重新提交
4. 讲师批改：通过 / 退回补充
5. 学员接收批改反馈

### 2.2 范围外【建议，需确认】
- 作业成绩计入培训总成绩/学分体系
- 作业查重、AI 检测
- 同伴互评
- 线下作业（纸质提交）
- 作业催交短信/电话提醒

---

## 三、角色与权限

| 角色 | 权限 |
|---|---|
| **系统管理员** | 班级/人员管理、全局配置（文件大小、类型限制）、数据导出 |
| **讲师** | 创建/发布/撤回作业、查看提交列表、下载文件、批改（通过/退回）、填写评语 |
| **学员** | 查看作业要求、上传/重新提交、查看批改结果与评语 |
| **培训管理员（建议）** | 查看所有班级作业完成率、批改及时率等统计 |

【建议】讲师是否可修改已发布作业的截止时间、是否允许助教代批改，需确认（见第八节）。

## 四、完整流程

### 4.1 主流程

```
讲师发布作业 → 学员查看 → 学员提交 → (截止前可重新提交)
→ 截止 → 讲师批改 → 通过 / 退回补充
→ 退回后学员补充提交 → 讲师复审 → 通过
→ 全员收到反馈，流程结束
```

### 4.2 流程步骤说明

**步骤 1：讲师发布作业**
1. 讲师选择班级/学员范围，填写：作业标题、说明、附件（可选）、截止时间
2. 系统校验截止时间须晚于当前时间【建议：至少留 24 小时】
3. 发布后学员端即时可见，并发通知

**步骤 2：学员提交**
1. 学员在作业详情页上传文件
2. 系统校验：文件类型、大小、是否在截止前
3. 提交成功后状态变为「已提交」，记录提交时间

**步骤 3：重新提交（截止前）**
1. 学员可查看已提交版本，点击「重新提交」
2. 【建议】新版本覆盖旧版本，但旧版本保留在历史记录中，讲师默认查看最新版
3. 每次重新提交均更新提交时间戳

**步骤 4：截止**
1. 到达截止时间后，提交入口自动关闭
2. 【建议】截止前 24 小时、1 小时各发一次提醒

**步骤 5：讲师批改**
1. 讲师进入批改列表，下载文件查看
2. 选择结果：**通过**（可附评语）或 **退回补充**（必须填写退回原因/评语）
3. 批改后系统通知学员

**步骤 6：退回补充**
1. 【建议】退回时设置补充截止时间（默认原截止时间 + 3 天，讲师可改）
2. 学员在补充截止前重新上传
3. 讲师复审，可再次退回【建议：限制退回次数上限，如 3 次，避免无限循环】

**步骤 7：结束**
- 作业状态变为「已通过」或「已截止未通过」，学员可查看最终评语

## 五、状态定义与异常处理

### 5.1 作业状态机（学员视角）

| 状态 | 触发条件 | 可执行操作 |
|---|---|---|
| 待提交 | 作业已发布，未提交 | 提交 |
| 已提交 | 提交成功，未截止 | 重新提交 |
| 已截止-未提交 | 截止且无提交 | 无（或申请延期） |
| 待批改 | 截止后等待讲师 | 无 |
| 已退回 | 讲师退回补充 | 补充提交 |
| 已通过 | 讲师通过 | 查看评语 |
| 已截止-未通过 | 补充截止仍未通过 | 查看结果 |

### 5.2 异常场景

| 异常 | 处理方案 |
|---|---|
| 截止后学员尝试提交 | 系统拦截，提示已截止；【建议】提供「申请延期」入口，讲师审批 |
| 上传中断/失败 | 支持断点提示，保留本地文件，提示重试 |
| 文件超限/类型不符 | 前端+后端双重校验，明确报错提示 |
| 讲师批改前作业被撤回 | 【建议】已有人提交则禁止撤回，只允许「关闭作业」并通知 |
| 退回后学员始终未补充 | 到补充截止时间自动关闭，状态「已截止-未通过」 |
| 讲师长期未批改 | 【建议】超期 X 天向讲师和培训管理员发送催办 |
| 学员中途退出培训/转班 | 已提交记录保留归档，不再计入待办 |
| 重复提交冲突（多端同时操作） | 以服务器时间为准，后提交覆盖并提示 |

## 六、数据与留痕

### 6.1 核心数据实体

| 实体 | 关键字段 |
|---|---|
| 作业 | 作业ID、标题、说明、附件、发布时间、截止时间、发布人、状态 |
| 提交记录 | 提交ID、作业ID、学员ID、文件、提交时间、版本号 |
| 批改记录 | 批改ID、提交ID、讲师ID、结果（通过/退回）、评语、批改时间、退回次数 |
| 通知记录 | 通知ID、接收人、类型、发送时间、已读状态 |

### 6.2 留痕要求【建议】
1. **版本留痕**：每次提交/重新提交均保留完整记录，不物理删除
2. **操作日志**：发布、修改截止时间、批改、退回等关键操作记录操作人、时间、前后值
3. **文件存储**：文件保留至培训周期结束后至少 1 年（具体期限需与法务确认）
4. **不可篡改**：批改结果一经提交不可修改；如需更正，走「批改申诉」流程并留痕

## 七、验收标准

### 7.1 功能验收
- [ ] 讲师可成功发布作业，学员端可见并收到通知
- [ ] 学员可上传文件，截止前重新提交成功，历史版本可查
- [ ] 截止后提交入口自动关闭，无法提交
- [ ] 讲师可批改：通过/退回，退回必须填写原因
- [ ] 退回后学员可补充提交，讲师可复审
- [ ] 每个状态变更均有对应通知送达学员/讲师
- [ ] 所有操作留痕可查询

### 7.2 验收方式
- 按第五节状态机编写测试用例，覆盖全部状态流转与异常场景
- 【建议】组织 1 个试点班级真实使用一轮后正式验收
