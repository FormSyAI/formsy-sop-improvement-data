# 产品 SOP：对话式数据查询工具「修改与删除历史问题」

## 0. 文档说明

本文档区分三类内容：

- ✅ **已明确**：需求方在开发请求中已明确规定的
- 💡 **建议**：设计建议，需需求方确认后方可执行
- ❓ **待定**：需求方必须补充决定，否则无法进入制作

---

## 1. 需求范围

### 1.1 已明确（✅）

1. 用户可**修改**历史问题。修改后，Agent 结合之前的对话上下文重新回答。
2. 用户可**删除**历史问题。删除时，**同时删除该问题及其后续所有回答**，并更新对话历史。

### 1.2 范围外（本次不做）

- 不涉及代码实现细节
- 不涉及批量编辑、问题重命名、对话分支（fork）等扩展功能（💡 建议列为后续迭代）
- 不涉及多人协作编辑同一对话（❓ 需确认是否存在多用户共享对话场景）

### 1.3 核心设计原则

- **一致性原则**：对话历史（用户看到的）与 Agent 实际使用的上下文（发给模型的）必须是同一份数据，不允许出现“显示已删但模型仍记得”的情况。
- **因果链原则**：一个问题及其回答、图表构成一个“消息组”；删除问题即级联删除其后所有消息组。

---

## 2. 核心概念与数据模型（产品层面）

### 2.1 消息组

每次用户提问产生一个**消息组**，包含：

| 元素 | 说明 |
|---|---|
| 问题 | 用户输入的自然语言问题 |
| 回答 | Agent 生成的分析结果 |
| 图表 | 回答中生成的可视化（可能为空） |
| 序号 | 在对话中的位置（第 N 轮） |

### 2.2 对话历史

- 对话 = 按序排列的消息组列表。
- Agent 每次回答时，实际使用的上下文 = 当前数据源 + 此前所有消息组（问题+回答）。
- ✅ 关键约束：**修改/删除操作必须原子性地同时更新“展示层历史”和“Agent 上下文层”**，两者不允许出现中间不一致状态。

---

## 3. 用户行为与交互设计

### 3.1 操作入口

✅ 已明确：用户可修改和删除历史问题。

💡 **建议**（需确认）：入口位置为——

1. **悬停消息组**：鼠标悬停在某个历史问题上时，显示操作图标（编辑 ✏️、删除 🗑️）。
2. **问题文本旁的“更多”菜单**：点击问题右侧 `···`，弹出菜单含“修改问题”“删除此问题及后续内容”。
3. **移动端**：长按问题弹出操作菜单。

❓ 待定：是否允许对**回答**单独操作（如仅删除回答保留问题）？建议不允许，保持“问题-回答”原子性。

### 3.2 修改问题流程

**正常路径：**

1. 用户点击某历史问题的“修改”。
2. 该问题进入**编辑态**：问题文本变为可编辑输入框，预填原问题；该问题对应的回答和图表置灰/半透明，并显示提示“修改后将重新生成回答”。
3. 用户修改文本（示例：将“华东地区增长最快的产品是什么？”改为“华南地区增长最快的产品是什么？”），点击“重新提问”（或按回车）。
4. 系统行为：
   - 保留该问题**之前**的所有消息组不变（含第 1 轮“去年各地区销售额”）。
   - 该问题的回答进入生成中状态（loading），旧回答暂时隐藏或置灰。
   - Agent 使用“之前的历史 + 修改后的问题”重新生成回答和图表。
   - **该问题之后的所有消息组**：💡 建议两种方案，需需求方选择：
     - **方案 A（推荐）**：后续消息组全部删除。因为后续回答基于旧问题，逻辑上已失效。
     - **方案 B**：后续消息组保留但标记为“基于旧版本问题生成，可能已失效”，用户可手动触发重算。
   - ❓ 待定：方案 A 还是 B？（示例场景中第 3 轮“画成图”依赖第 2 轮回答，若第 2 轮被修改，第 3 轮必须处理）
5. 生成完成后，新回答替换旧回答，图表同步更新。
6. 用户可取消编辑（点击“取消”），一切恢复原状，不产生任何变更。

**修改后各元素变化表：**

| 元素 | 变化 |
|---|---|
| 被修改的问题 | 文本更新为新问题 |
| 该问题的回答 | 重新生成 |
| 该回答的图表 | 随新回答重新生成 |
| 之前的历史 | 不变 |
| 之后的历史 | 方案 A：删除 / 方案 B：标记失效（❓待定） |

### 3.3 删除问题流程

**正常路径：**

1. 用户点击某历史问题的“删除”。
2. 💡 建议：弹出确认框：“将删除此问题及其后 N 条问答（含图表），是否继续？”——因为级联删除影响大，需二次确认。❓ 待定：是否需要确认框，还是直接删除+可撤销？
3. 用户确认后：
   - 该消息组（问题+回答+图表）删除。
   - 其后所有消息组级联删除。
   - 对话历史立即更新；Agent 后续上下文同步移除这些内容。
4. 💡 建议：删除后显示 toast“已删除 N 条问答”，并提供 5–10 秒“撤销”能力（❓ 待定：是否需要撤销功能，涉及已删数据暂存机制）。

**删除后各元素变化表：**

| 元素 | 变化 |
|---|---|
| 被删问题及回答、图表 | 删除 |
| 其后所有消息组 | 级联删除 |
| 之前的历史 | 不变 |
| Agent 上下文 | 同步移除，后续提问不再“记得”被删内容 |

### 3.4 边界情况

| 情况 | 行为 |
|---|---|
| 修改/删除**第一条**问题 | 允许；修改后等于全新回答（无前置上下文）；删除后对话可能为空 |
| 删除**最后一条**问题 | 允许；仅删除该条 |
| 对话中只剩一条消息时删除 | 对话回到空状态，显示初始引导 |
| 修改后问题文本与原问题相同 | 💡 建议：提示“问题未变化”，不触发重新生成 |
| Agent 正在生成回答时用户发起修改/删除 | ❓ 待定。💡 建议：禁止操作该条及之后的消息（按钮置灰），之前的消息可正常操作；或允许操作但需中断生成。需需求方确认。 |

## 4. 状态定义

| 状态 | 说明 | 可用操作 |
|---|---|---|
| 空对话 | 无任何消息 | 无历史操作可用 |
| 稳定 | 所有回答已生成完毕 | 可修改/删除任意历史问题 |
| 生成中 | Agent 正在回答最新问题 | 💡 建议：历史操作受限（见 3.4） |
| 编辑态 | 某问题正在被修改 | 该消息组：保存/取消；其他消息组操作 💡 建议暂时锁定 |
| 删除确认中 | 确认框弹出 | 确认/取消 |

---

## 5. 角色、权限与适用范围

✅ 已明确：操作者为提问用户本人。

| 角色 | 权限 |
|---|---|
| 对话所有者 | 修改、删除本对话中任意历史问题 |
| 其他用户 | ❓ 待定：是否存在共享对话？若有，谁能改/删？建议默认仅所有者可操作 |
| 管理员 | ❓ 待定：是否可查看/恢复已删内容（审计需求） |

❓ 待定：删除是否为软删除（服务端保留可恢复）还是硬删除（彻底清除）？影响撤销功能和审计。

---

## 6. 异常路径

| 异常场景 | 处理 |
|---|---|
| 修改后重新生成失败（模型/服务错误） | 💡 建议：保留原问题原回答，显示错误提示+“重试”按钮；不产生半删除状态 |
| 删除请求失败（网络错误） | 对话保持原状，提示“删除失败，请重试”；不允许出现“前端已删、后端未删”的不一致 |
| 修改提交后用户刷新/离开页面 | ❓ 待定。💡 建议：编辑中内容暂存草稿；生成中断开则该轮标记为“生成中断”，可重试 |
| 上下文同步失败（历史已更新但 Agent 上下文未更新） | ✅ 属于必须防御的核心异常：任何操作必须以服务端事务方式完成，失败则整体回滚 |
| 修改后新回答生成中用户又想再改 | 💡 建议：生成中锁定编辑入口 |

## 8. 验收标准

### 8.1 修改功能

- [ ] 用户可从指定入口进入任意历史问题的编辑态，预填原文。
- [ ] 取消编辑后，问题、回答、图表完全不变。
- [ ] 修改并提交后，新回答基于“之前历史+新问题”生成（验收方法：修改示例第 2 轮为华南地区，新回答内容应针对华南）。
- [ ] 修改后图表与新回答一致。
- [ ] 修改后立即提出新问题，Agent 的回答不体现被替换的旧问题内容（上下文一致性验收）。
- [ ] 生成失败时原对话内容完整保留。

### 8.2 删除功能

- [ ] 删除第 2 轮问题后，第 2、3 轮（含图表）全部消失，第 1 轮保留。
- [ ] 删除后提出新问题，Agent 回答不引用任何被删内容（如不再“记得”华东分析）。
- [ ] 删除最后一条、删除第一条、删除唯一一条均正常。
- [ ] 删除失败时对话无变化。

### 8.3 一致性（核心验收项）

- [ ] 任意修改/删除操作后，界面展示的历史与 Agent 实际使用的上下文 100% 一致（通过对比请求中携带的上下文与界面内容验证）。
- [ ] 并发/中断场景下不出现中间不一致状态。
