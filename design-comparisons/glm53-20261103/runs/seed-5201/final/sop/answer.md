## 1. 用户、问题与范围

### 1.1 用户与问题

- 使用者：上传销售数据并用自然语言连续提问的分析人员（单人使用）。
- 困难：问题问错后无法修正，错误问题污染后续上下文。
- 目标：可修改/删除任意历史问题（含第一条），历史与 Agent 上下文保持一致。

### 1.2 范围（【已确认】）

| 项 | 状态 |
| --- | --- |
| 修改任意历史问题（含第一条），结合之前对话重新回答 | 【已确认】在范围内 |
| 删除任意历史问题（含第一条）及其后全部问答 | 【已确认】在范围内 |
| 数据集在删除第一条问题后保留 | 【已确认】 |
| 手动重新执行已失效问题 | 【已确认】在范围内 |
| 删除撤销、批量编辑、多人协作、编辑 Agent 回答 | 【已确认】本轮范围外 |

## 3. 修改与删除的行为设计（【已确认】）

### 3.1 修改第 N 个问题（Q_N）

**正常路径**：
1. Q_N 进入编辑态，原文保留，取消则无任何变化。
2. 提交后：Q_N 文本替换为新问题。
3. 第 1 至 N-1 轮的问题、回答和图表**原样保留**。
4. 原 A_N 及其图表**失效**（不再进入上下文）。
5. 系统以 Q_1…Q_{N-1} + 新 Q_N 为上下文重新生成回答 A'_N。
6. Q_N 之后的原问题文本**继续展示**，但其旧回答和图表**全部失效**，不进入 Agent 当前上下文。
7. 系统**不自动重跑**后续问题；用户可对已失效问题逐个手动重新执行。

**失效展示**：【建议】失效回答/图表以视觉标记（如置灰、“已失效”标签）呈现，并附“重新执行”入口；具体样式待确认。

**手动重新执行**：【已确认】能力存在。重新执行 Q_k（k>N）时，上下文 = 当前所有有效问答（含 A'_N 及此前已重新执行的回答）。【建议】重新执行后生成新回答替换失效展示。

### 3.2 删除第 N 个问题

**正常路径**：
1. 删除 Q_N、A_N 及其图表。
2. 同时删除其后**全部**问题和问答内容，直到对话末尾。
3. 第 1 至 N-1 轮保留；数据集保留。
4. 删除第一条问题后：对话历史为空，用户可从数据集重新提问。

### 3.3 图表规则

| 情况 | 行为 | 状态 |
| --- | --- | --- |
| 修改后新回答含图表 | 新图表随 A'_N 生成 | 【已确认】（推论） |
| 修改后原回答/图表 | 失效，不进入上下文 | 【已确认】 |
| 后续问题的旧图表 | 全部失效 | 【已确认】 |
| 删除问题 | 该问题及后续全部问答与图表删除 | 【已确认】 |
| 已导出图表副本是否受影响 | 未提及 | 【未知】若已有导出功能需决定 |

### 3.4 上下文一致性不变量（【已确认】）

**INV-1**：Agent 当前上下文 = 界面中仍然**有效**并展示的问答序列。失效回答、已删除内容一律不在上下文中。

- 修改 Q_N 后：上下文 = Q_1…Q_{N-1}（含回答）+ 新 Q_N + A'_N（成功后）+ 此后手动重新执行成功的问答。
- 删除 Q_N 后：上下文 = Q_1…Q_{N-1}（含回答）。
- 【建议】实现原则：对话历史（含每条问答的有效/失效状态）为唯一事实源，上下文由其派生。技术承接方式（重放/增量维护）为技术待承接项 H1。

## 4. 状态与权限

### 4.1 问答条目状态（【已确认】语义，命名【建议】）

```
正常(有效) → 编辑中 → 重答中 → 有效(新回答) 
                     ↘ 回答失败(可重试)
正常(有效) → 已失效（因前序问题被修改；可手动重新执行 → 重答中）
正常(有效) → 已删除（随本条或前序问题删除，不可见）
```

| 状态 | 含义 | 出口 |
| --- | --- | --- |
| 有效 | 在上下文中 | 可被修改/删除/因前序修改而失效 |
| 失效 | 展示但不在上下文 | 手动重新执行 → 重答中；或随删除消失 |
| 重答中 | 等待新回答 | → 有效 / 失败 |
| 失败 | 新问题文本保留，旧回答仍失效 | 重试 → 重答中 |

### 4.2 角色与权限

- 【已确认】单人使用，用户对自己的对话拥有全部修改/删除权限；无多人协作（本轮范围外）。
- 【建议】无需额外角色/权限校验设计。

## 5. 异常路径

| 异常 | 产品行为 | 状态 |
| --- | --- | --- |
| 修改后重答失败 | 新问题文本保留；旧回答和图表仍失效；界面提供重试 | 【已确认】 |
| 重试再次失败 | 【建议】保持失败态，可继续重试；重试次数/费用边界【未知】 |
| 编辑提交为空 | 【建议】禁止提交并提示；待确认 | 【未知】 |
| 删除/修改正在生成回答的问题 | 未答复 | 【未知】（建议：生成中条目操作禁用或先取消，待确认） |
| 操作中页面刷新/中断 | 未答复 | 【未知】（建议以服务端历史为准恢复） |
| 修改后新问题无法回答 | 【建议】按现有“无法回答”行为处理，不回滚修改 | 待确认 |
| 手动重新执行失败 | 【建议】同重答失败处理：问题文本保留、回答保持失效、可重试 | 待确认（由第 7 条推论） |

## 7. 已确认 vs 剩余未知

**已确认**：任意问题（含第一条）可修改/删除；修改保留前序、失效本条及后续旧回答、不自动重跑、支持手动重新执行；删除级联到末尾、数据集保留；上下文 = 界面有效展示的问答；本轮不做撤销/批量/协作/编辑回答；失败时新问题保留、旧回答失效、可重试。

**剩余未知（按影响排序）**：
1. 删除/修改正在生成回答中的问题时的行为（影响状态机完整性）。
2. 空编辑提交、操作中断恢复的细节。
3. 失效条目的具体展示样式与“重新执行”入口形态。
4. 已导出图表副本在源回答删除/失效后是否受影响（若已有导出功能）。
5. 重试次数/费用边界。

**技术待承接（H 项）**：
- H1：上下文由“历史 + 有效状态”派生的实现机制（重放 vs 增量维护）及性能/费用影响。
- H2：修改/删除/失效状态的持久化与中断恢复。
- H3：重答与重新执行失败的服务错误分类与重试边界。
