# 产品 SOP（最终版）：对话式数据分析工具「修改与删除历史问题」

## 0. 文档说明

本文档基于需求方补充答复更新，内容分为三类：

- **【已确认】**：需求方已明确决定的行为
- **【建议】**：设计建议方案，待需求方确认
- **【待定】**：仍需需求方补充决定的事项

本文档仅为产品设计与实施计划，不涉及代码实现。

---

## 1. 范围与目标

### 1.1 范围内

- 用户对任意历史问题（含第一条）发起**修改**或**删除**
- 修改后基于「前序有效对话 + 新问题」重新生成回答
- 删除后移除该问题及其后全部问答，并更新对话历史
- 对话历史与 Agent 实际使用上下文的一致性保障
- 相关状态、异常路径与验收标准

### 1.2 范围外（本轮明确不做）【已确认】

- 删除撤销 / 回收站
- 批量编辑 / 批量删除
- 多人协作
- 重新编辑 Agent 回答

---

## 2. 操作入口与可操作对象

| 位置 | 操作 | 状态 |
|------|------|------|
| 历史问题气泡（用户消息）悬浮/点击菜单 | 「修改」「删除」 | 【已确认】任意历史问题均可操作，含第一条 |
| 修改入口点击后 | 问题气泡变为原位编辑框，预填原问题，可提交或取消 | 【建议】原位编辑，保留对话位置感 |
| 删除入口点击后 | 【建议】二次确认，提示“将删除此问题及其后全部问答，不可恢复” | 【待定】是否需要二次确认（撤销已确认不做，故建议保留确认） |
| Agent 回答气泡 | 不提供修改/删除入口 | 【已确认】回答不可编辑；只能通过其对应问题连带处理 |
| 已失效问题（旧回答失效后） | 提供「重新执行」入口 | 【已确认】用户可手动重新执行已失效的问题 |

---

## 3. 修改与删除的行为定义

### 3.1 修改第 N 个问题【已确认】

1. 第 1 至 N-1 轮：原问题、回答、图表**全部保留**，不受影响。
2. 第 N 个问题：文本替换为新问题；**原回答和图表失效**（不再展示为有效内容，不进入上下文）。
3. 第 N+1 及之后的问题：**原问题文本继续展示**，但其旧回答和图表**全部失效**，不进入 Agent 当前上下文。
4. 系统**不自动重跑**后续问题；用户可对失效问题逐个手动「重新执行」。
5. 修改提交后，Agent 以「第 1 至 N-1 轮有效问答 + 新的第 N 个问题」为上下文，生成新回答（含图表，如适用）。

**失效问题的展示方式**【建议】：
- 失效问题文本保留展示，其回答区域显示“此回答已因前序问题修改而失效，可重新执行”。
- 失效问题在视觉上与有效问答区分（如置灰、标记“已失效”）。
- 【待定】失效问答是折叠展示、置灰展示还是仅保留问题文本——具体视觉形式待需求方确认。

### 3.2 删除第 N 个问题【已确认】

1. 删除第 N 个问题、其回答和图表。
2. **同时删除其后的全部问题和问答内容，直到当前对话末尾**（与修改不同：删除是物理移除，不是失效标记）。
3. 第 1 至 N-1 轮保持不变。
4. **第一条问答之前上传的数据集继续保留**——删除问题不影响数据集。

### 3.3 删除第一条问题【已确认】

- 允许删除。删除后对话历史变为**空会话**，数据集保留，用户可从数据集重新提问。

### 3.4 图表变化汇总

| 场景 | 图表行为 |
|------|----------|
| 修改第 N 问 | 第 N 问原图表失效；新回答重新生成图表（如适用）；N+1 及之后的图表全部失效 |
| 删除第 N 问 | 第 N 问及其后所有图表**删除** |
| 第 1 至 N-1 轮 | 图表保持不变 |
| 重新执行失效问题 | 基于当前有效上下文重新生成回答与图表 |

## 4. 对话历史与 Agent 上下文一致性

**核心规则【已确认】**：修改或删除后，Agent 当前上下文**只能使用界面中仍然有效并展示的问答**。

### 4.1 设计原则

1. **单一事实来源**：后端维护权威会话消息序列（含消息 ID、状态：有效/失效/已删除），前端仅为渲染层。
2. **上下文构建规则**：Agent 每次回答（含新提问、修改后重答、重新执行失效问题）时，从权威序列按顺序取「全部状态为有效」的消息构建上下文。失效和已删除消息一律排除。
3. **修改 = 替换 + 标记失效**：第 N 问替换文本，其回答及后续回答标记失效；后续问题文本保留但标记“待重新执行”。
4. **删除 = 截断**：权威序列从第 N 问处截断移除。
5. **重新执行的上下文**：重新执行第 M 个失效问题时，上下文 = 第 1 至 M-1 轮中当前有效的问答 + 第 M 个问题。若 M 之前仍有失效未重跑的问答，则这些失效内容不进入上下文。

### 4.2 一致性保障机制【建议】

- 修改/删除/重新执行操作与上下文状态更新在同一原子流程中完成，操作成功后才允许发起新提问。
- 操作请求返回成功前，输入框置为不可发送状态，避免竞态。
- 为会话维护版本号，多端并发操作时后操作方收到“会话已更新”提示并刷新。

---

## 5. 状态定义

| 状态 | 说明 | 允许的操作 |
|------|------|-----------|
| 有效 | 问题与回答均为当前上下文内容 | 问题可修改、可删除 |
| 生成中 | Agent 正在回答该问题 | 【建议】禁止修改/删除该问题及之前的问题 |
| 生成失败 | 回答出错 | 可修改、可删除、可重试 |
| 失效（因前序修改） | 问题文本展示，回答/图表失效，不进入上下文 | 可「重新执行」；【待定】失效问题本身是否仍可修改/删除 |
| 已删除 | 已从权威序列移除 | 不可见、不可操作 |

**角色与权限**【待定】：需求未说明是否存在共享会话或管理员角色。默认建议：仅会话所有者可操作自己的会话。若存在会话共享，需需求方补充被共享者的操作权限边界。

## 6. 正常路径与异常路径

### 6.1 正常路径

**修改**：
1. 点击问题 →「修改」→ 气泡变为编辑框，预填原文
2. 修改文本 → 提交 → 前端锁定输入，显示“更新中”
3. 后端替换问题文本，标记原回答及后续回答失效，触发重新生成第 N 问回答
4. 新回答（含图表）生成展示；后续失效问题展示文本 + “可重新执行”入口

**删除**：
1. 点击问题 →「删除」→（建议）二次确认
2. 确认 → 前端锁定，显示“删除中”
3. 后端截断权威序列，返回成功
4. 前端移除该问题及其后全部问答与图表；若删除第一条，会话为空，数据集保留

**重新执行失效问题**：
1. 用户点击失效问题的「重新执行」
2. Agent 以「当前有效前序问答 + 该问题」为上下文重新生成回答与图表
3. 该问题及回答恢复为有效状态

### 6.2 异常路径

| 异常 | 处理 | 状态 |
|------|------|------|
| 修改后重新生成失败 | **【已确认】**新问题文本保留，旧回答和图表仍失效；界面提供重试入口 | 已确认 |
| 修改/删除请求失败（网络/服务错误） | 【建议】前端恢复操作前状态并提示错误，权威序列不变 | 建议 |
| 生成中尝试修改/删除 | 【建议】入口置灰或提示“请等待当前回答完成”；【待定】是否提供“停止生成” | 建议/待定 |
| 并发冲突（多端操作同一会话） | 【建议】基于会话版本号，后操作方收到“会话已更新”提示并刷新 | 建议 |
| 修改后问题为空/超长 | 【建议】前端校验：非空、长度上限沿用新建问题规则 | 建议 |
| 重新执行失败 | 【建议】问题保持失效状态，显示失败提示与重试入口 | 建议 |
| 重新执行时前序仍有失效问答 | 【建议】失效内容不进入上下文（按已确认规则第 5 条执行）；【待定】是否提示用户“前序存在未重新执行的失效问答” | 建议/待定 |

## 8. 验收标准

### 修改功能

- [ ] 任意历史问题（含第一条）可进入编辑态，预填原文，取消无副作用
- [ ] 修改第 N 问后：第 1 至 N-1 轮问答与图表完全不变
- [ ] 第 N 问文本更新，原回答与图表失效，基于「前序有效对话 + 新问题」生成新回答
- [ ] 第 N+1 及之后的问题文本仍展示，其旧回答与图表全部失效
- [ ] 系统不自动重跑后续问题；每个失效问题有「重新执行」入口
- [ ] 重新执行失效问题后，其回答基于当前有效上下文生成，并恢复为有效状态
- [ ] 修改后生成失败：新问题文本保留，旧回答仍失效，有明确失败提示与重试入口

### 删除功能

- [ ] 删除第 N 问后，第 N 问及其后全部问答与图表从界面和存储中消失，第 1 至 N-1 轮不变
- [ ] 删除第一条问题后会话为空，数据集保留，可重新提问
- [ ] 删除操作不影响已上传的数据集

### 上下文一致性

- [ ] 修改/删除后继续提问，Agent 上下文仅包含界面中有效且展示的问答（可通过追问“我刚才问了什么”验证）
- [ ] 失效问答不进入上下文（含重新执行场景）
- [ ] 修改/删除/重新执行成功前输入框不可发送新问题
- [ ] 操作失败时界面与存储均回滚至操作前状态
- [ ] 刷新页面后界面与权威序列完全一致

### 范围外验证

- [ ] 确认无删除撤销、批量操作、多人协作、回答编辑入口

## 9. 剩余待需求方决定的事项

1. **删除二次确认**：撤销功能已确认不做，是否保留删除前的二次确认弹窗？（建议保留）
2. **失效问答的展示形式**：折叠、置灰、还是仅保留问题文本 + 失效提示？
3. **失效问题本身是否可修改/删除**：失效状态下，「修改」「删除」入口是否仍可用？
4. **生成中的操作限制**：是否提供“停止生成”？生成中是否允许操作更早的问题？
5. **重新执行的前序提示**：重新执行第 M 问时，若第 1 至 M-1 轮中仍有失效问答，是否提示用户？
6. **角色与权限**：是否存在共享会话/管理员角色？他人会话的操作权限边界？
7. **失效内容的保留期限**：失效问答是否永久保留在存储中，还是有清理策略？（涉及存储与合规）
