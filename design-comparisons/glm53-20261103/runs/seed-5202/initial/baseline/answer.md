# 产品 SOP：对话式数据分析工具「修改与删除历史问题」

## 0. 文档说明

本文档区分三类内容：

- **【已明确】**：开发请求中已规定的行为
- **【建议】**：设计建议方案，待需求方确认
- **【待定】**：需求方必须补充决定的事项

本文档仅为产品设计与实施计划，不涉及代码实现，不代表任何功能已开发、测试或上线。

---

## 1. 范围与目标

### 1.1 范围内

- 用户对历史问题（用户消息）发起**修改**或**删除**操作
- 修改后基于更新后的对话上下文重新生成回答
- 删除后移除该问题及其后续所有回答，并更新对话历史
- 对话历史与 Agent 实际使用上下文的一致性保障
- 相关状态、权限、异常路径与验收标准

### 1.2 范围外（本次不做）

- 修改回答内容（Agent 生成的回答不可编辑）
- 跨会话批量删除
- 回收站 / 撤销删除
- 多人协作编辑同一会话

---

## 2. 用户可在哪些位置做什么

### 2.1 操作入口

| 位置 | 操作 | 状态 |
|------|------|------|
| 历史问题气泡（用户消息）悬浮/点击菜单 | 「修改」「删除」 | 【已明确】需提供修改与删除入口 |
| 修改入口点击后 | 问题气泡变为可编辑输入框，预填原问题，用户可修改后提交或取消 | 【建议】采用“原位编辑”而非弹窗，保留对话位置感 |
| 删除入口点击后 | 【建议】弹出二次确认，提示“将删除此问题及其后所有回答，不可恢复” | 【待定】是否需要二次确认、是否支持撤销 |
| Agent 回答气泡 | 不提供修改/删除入口 | 【建议】回答不可单独删除，只能通过删除其对应问题连带处理 |

### 2.2 可操作对象

- **【已明确】**：可修改/删除的对象是历史问题（用户消息）
- **【建议】**：仅允许操作“已回答完成”的问题；正在生成中的回答不可修改/删除其问题（见异常路径）
- **【待定】**：是否允许修改/删除**第一个问题**（删除后整个会话是否变为空会话，还是禁止删除第一条）

---

## 3. 修改/删除后的行为定义

### 3.1 修改问题

**【已明确】**：修改后结合之前的对话重新回答。

具体行为：

1. 用户提交修改后的问题
2. 该问题的**原回答被标记为失效并移除**（或折叠显示“原回答已因问题修改而更新”）
3. Agent 以「该问题之前的全部对话 + 修改后的问题」为上下文，重新生成回答
4. 该问题**之后**的历史问答如何处理：

**【待定——关键决策点】**：
- **方案 A（建议）**：修改点之后的所有问答一并清除，用户需重新追问（实现简单、语义最干净）
- **方案 B**：保留后续问答但标记为“基于旧版本问题生成”，可能存在上下文矛盾
- **建议采用方案 A**，与删除行为保持一致的语义，降低用户理解成本

5. 图表：原问题关联的图表随原回答一并移除；新回答若含图表则重新生成

### 3.2 删除问题

**【已明确】**：删除问题时同时删除该问题及其后续回答，并更新对话历史。

具体行为：

1. 删除目标问题 Qn
2. 连带删除 Qn 的回答 An，以及 Qn 之后的所有问答（Qn+1/An+1…）
3. Qn **之前**的问答保持不变
4. 所有被删除问答关联的图表一并移除
5. 对话历史（前端展示与后端存储）同步更新

### 3.3 图表变化汇总

| 场景 | 图表行为 |
|------|----------|
| 修改问题 | 原图表随原回答移除，新回答重新生成图表（如适用） |
| 删除问题 | 该问题及后续问答的图表全部移除 |
| 未受影响的问题 | 图表保持不变 |

---

## 4. 对话历史与 Agent 上下文一致性

**【已明确】**：需保证对话历史与 Agent 后续实际使用的上下文一致。

### 4.1 设计原则

1. **单一事实来源**：后端维护一份权威的会话消息序列（含消息 ID、状态、版本），前端展示仅为渲染层
2. **修改即重写**：修改问题后，权威序列中该消息被替换为新版本，其后消息被清除；Agent 后续提问的上下文构建完全基于该权威序列
3. **删除即截断**：删除问题后，权威序列从该消息处截断
4. **上下文构建规则**：Agent 每次回答时，从权威序列按顺序取「全部保留消息」构建上下文，不依赖任何本地缓存或前端状态

### 4.2 一致性保障机制

- 【建议】修改/删除操作与上下文重建在同一事务/原子流程中完成，操作成功后才允许发起新提问
- 【建议】前端在修改/删除请求返回成功前，将输入框置为不可发送状态，避免竞态
- 【建议】为会话维护版本号，操作时校验版本，防止并发修改冲突（见异常路径）

---

## 5. 状态、角色与权限

### 5.1 消息/会话状态

| 状态 | 说明 | 允许的操作 |
|------|------|-----------|
| 已回答 | 问题已有完成回答 | 可修改、可删除 |
| 生成中 | Agent 正在回答 | 【建议】禁止修改/删除该问题及之前的任何问题 |
| 生成失败 | 回答出错 | 【建议】可修改、可删除，也可重试 |
| 已失效 | 因前序修改/删除被清除 | 不展示或折叠展示，不可操作 |

### 5.2 角色与权限

**【待定】**：本产品的用户角色体系未在需求中说明。以下为建议默认方案：

| 角色 | 权限 |
|------|------|
| 会话所有者 | 修改/删除自己会话中的任意历史问题 |
| 其他用户 | 【建议】默认无权限访问他人会话；若存在共享会话功能，是否允许被共享者修改/删除为【待定】项 |
| 管理员 | 【待定】是否可管理用户会话内容（涉及数据合规，需需求方决定） |

## 6. 正常路径与异常路径

### 6.1 正常路径

**修改**：
1. 用户点击问题 → 选择「修改」→ 气泡变为编辑框
2. 修改文本 → 提交 → 前端锁定输入，显示“更新中”
3. 后端更新权威序列，清除后续消息，触发重新生成
4. 新回答（含图表）生成并展示，历史更新完成

**删除**：
1. 用户点击问题 → 选择「删除」→（建议）二次确认
2. 确认 → 前端锁定，显示“删除中”
3. 后端截断权威序列，返回成功
4. 前端移除该问题及后续所有问答与图表

### 6.2 异常路径

| 异常 | 处理 |
|------|------|
| 修改后重新生成失败 | 【建议】保留修改后的问题，回答区显示“生成失败，可重试”，不自动回滚问题文本 |
| 修改/删除请求失败（网络/服务错误） | 【建议】前端恢复原状态并提示错误，权威序列不变 |
| 生成中尝试修改/删除 | 【建议】入口置灰或提示“请等待当前回答完成”；【待定】是否允许“停止生成”功能配合 |
| 并发冲突（多端同时操作同一会话） | 【建议】基于会话版本号，后操作方收到“会话已更新”提示并刷新 |
| 删除第一条问题 | 【待定】禁止删除 vs 允许删除后会话为空 |
| 修改后问题为空/超长 | 【建议】前端校验：非空、长度上限沿用新建问题规则 |

## 8. 待需求方补充决定的事项汇总

1. **修改点之后的问答**：清除（方案 A）还是保留标记（方案 B）？——建议方案 A
2. **删除第一条问题**：是否允许？允许后会话如何呈现？
3. **删除二次确认与撤销**：是否需要？是否需要回收站？
4. **生成中的操作**：是否提供“停止生成”？生成中是否允许操作更早的问题？
5. **角色权限**：产品是否有共享会话/管理员角色？他人会话的操作权限边界？
6. **修改后重新生成失败**：是否回滚问题文本，还是保留新问题等待重试？
7. **失效消息展示**：被清除的历史是否需要任何痕迹（如“此处有已删除内容”提示），还是完全不可见？（涉及审计/合规，需确认）

## 9. 验收标准

### 修改功能

- [ ] 任意已回答的历史问题可通过入口进入编辑态，预填原文，可取消且无副作用
- [ ] 提交修改后，原回答及关联图表被移除，基于「前序对话 + 新问题」生成新回答
- [ ] （若确认方案 A）修改点之后的问答全部清除
- [ ] 修改后继续提问，Agent 上下文不包含任何被清除的旧内容（可通过追问验证，如“我刚才问了什么”）
- [ ] 生成失败时问题保留且有明确失败提示与重试入口

### 删除功能

- [ ] 删除 Qn 后，Qn 及其后所有问答与图表从界面和存储中消失，Qn 之前内容不变
- [ ] 删除后继续提问，Agent 上下文不包含被删除内容
- [ ] 删除操作有（若确认）二次确认，取消删除无任何副作用

### 一致性与异常

- [ ] 修改/删除成功前输入框不可发送新问题
- [ ] 操作失败时界面与存储均回滚至操作前状态
- [ ] 生成中操作入口按设计禁用/提示
- [ ] 双端并发操作时，后操作方收到冲突提示并刷新至最新状态
- [ ] 刷新页面后对话历史与操作前界面完全一致（前端与权威序列同步）
