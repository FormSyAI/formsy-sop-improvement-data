# 产品 SOP：对话历史问题的修改与删除（草案 v0.1）

> 本文档为产品行为设计草案，未获需求方确认前不构成正式决定。文中明确区分：**已明确事实**（来自开发请求原文）、**建议方案**（待确认）、**未知/待决定**（需需求方补充）。

---

## 0. 范围与对象

- **产品**：自然语言数据查询工具（上传销售数据 → 连续提问 → Agent 分析 → 可生成图表）。
- **本次范围**：对已提交历史问题的**修改**与**删除**，及其对回答、图表、对话历史和 Agent 上下文的影响。
- **范围外（建议）**：上传数据文件的管理、多会话管理、回答内容的单独编辑、协作分享。是否纳入由需求方决定。

**已明确事实**：
1. 修改问题后，需结合之前的对话重新回答。
2. 删除问题时，删除该问题及其后续回答，并更新对话历史。

---

## 1. 用户与任务

| 项 | 内容 |
| --- | --- |
| 使用者 | 已上传数据、正在与 Agent 对话的查询用户 |
| 核心任务 | 修正问错的问题；清理不需要的问题及回答 |
| 当前困难 | 问题问错（如示例中“华东”应为“华南”）后无法修正，只能重新开一轮提问，上下文断裂 |
| 目标结果 | 修改后得到基于正确问题的、与上下文一致的新回答；删除后历史干净且后续回答不受已删内容影响 |

---

## 2. 用户可操作的位置与行为

### 2.1 操作入口（建议方案）

| 入口 | 位置 | 可执行动作 |
| --- | --- | --- |
| E1 | 每条历史问题气泡上的悬浮操作（编辑、删除） | 修改该问题 / 删除该问题 |
| E2 | 问题气泡点击进入编辑态 | 修改文本后重新提交 |
| E3 | 删除确认弹层 | 确认或取消删除 |

**建议**：编辑与删除入口仅出现在“问题”上，不出现在“回答”上（回答由 Agent 生成，用户不直接编辑回答）。

**待决定**：
- 是否允许批量删除（一次删多个问题）？
- 是否需要“撤销删除”？（影响数据保留设计，见 §7）

### 2.2 修改问题（F-EDIT）

| 字段 | 规定 |
| --- | --- |
| 触发 | 用户点击某条历史问题的“编辑” |
| 前置 | 该问题已提交且已有回答（或回答生成中，见异常 §6.3） |
| 输入 | 修改后的问题文本；非空；长度上限待决定 |
| 正常行为 | 提交后：原问题文本被替换为新文本；**原回答及由其衍生的图表作废并移除**；Agent 以新问题为输入，结合该问题之前的对话上下文重新生成回答；若原回答曾生成图表，新回答按 Agent 正常逻辑决定是否重新生成图表 |
| 可见输出 | 编辑的问题位置不变，显示新文本（是否保留“已编辑”标记：待决定）；下方出现新生成的回答 |
| 副作用 | 消耗一次 Agent 调用（费用/额度口径待决定）；原回答不再可访问（是否可恢复：待决定） |

**关键语义（建议，需确认）**：修改 = “替换该轮问答”。不是“追加一个新问题”。修改后，该问题**之后**的旧回答全部作废——因为后续回答依赖被改问题的上下文。

**待决定（影响最大，请逐项确认）**：
- **Q1**：修改后，该问题之后是否还存在后续轮次？若存在（如示例中第 3 问“画图”依赖第 2 问），后续问答是**一并作废**，还是**自动级联重新执行**？建议：一并作废，由用户自行决定是否重问；自动级联重答会产生多次调用费用且结果不可控。
- **Q2**：编辑是否保留原文痕迹（“已编辑”标记或可查看原问题）？

### 2.3 删除问题（F-DELETE）

| 字段 | 规定 |
| --- | --- |
| 触发 | 用户点击某条历史问题的“删除”并确认 |
| 前置 | 同 F-EDIT |
| 正常行为 | 该问题、其回答、其衍生图表，以及**该问题之后的所有问答及图表**从对话历史中移除；Agent 上下文同步更新为删除后剩余的对话 |
| 可见输出 | 对话界面收缩，剩余历史保持原顺序；后续新提问以剩余历史为上下文 |
| 副作用 | 被删内容不再影响后续回答；是否物理删除/可恢复：待决定 |

**已明确事实**：删除时“同时删除这个问题及其后续回答”——即级联删除，本 SOP 按此设计。若需求方本意是“仅删除该问题及其直接回答、保留后续”，请纠正（这是语义分歧点，当前按原文执行）。

**待决定**：
- **Q3**：删除是否需要二次确认？建议：需要，且确认文案说明“将同时删除其后 N 轮问答”。
- **Q4**：删除是否可撤销（如 10 秒内）？

## 3. 对话历史与 Agent 上下文一致性

**规则（建议）**：

1. **单一事实源**：对话历史（问题+回答+图表引用）是唯一权威记录；Agent 每次回答所使用的上下文 = 当前对话历史中该问题之前的全部剩余轮次。
2. **修改后**：上下文 = 被改问题之前的轮次 + 被改问题的新文本。被改问题之后的旧轮次不进入上下文（已作废）。
3. **删除后**：上下文 = 被删问题之前的轮次。被删问题及之后的所有轮次不进入上下文。
4. **图表**：图表是回答的派生物，随所属回答作废/删除而作废/删除；不存在脱离回答的独立图表历史。
5. **一致性断言（验收用）**：任意修改/删除操作后，用同一后续问题提问，Agent 的回答不得引用已作废/已删除轮次的内容（如已删的“华东”分析结论）。

**待决定**：
- **Q5**：上下文是否有长度/轮次上限？超出时截断策略是什么？（若现有产品已有规则，沿用并登记）

## 4. 状态设计

### 4.1 单轮问答状态

| 状态 | 含义 | 出口 |
| --- | --- | --- |
| 已提交（问题已保存，回答未生成） | 短暂中间态 | → 已回答 / 回答失败 |
| 已回答 | 问题+回答+可选图表完整展示 | 可被编辑/删除 |
| 回答失败 | Agent 调用失败，问题保留 | 可重试（待决定）/ 编辑 / 删除 |
| 已作废（因前序轮次被修改/删除） | 不再展示、不进上下文 | 若实现撤销可回到已回答；否则终态 |
| 已删除 | 从历史移除 | 若实现撤销删除可恢复；否则终态 |

### 4.2 编辑重答过程状态

编辑提交 → “重新生成中”（该位置显示加载态，原回答已移除）→ 成功（新回答替换）或失败（提示错误，问题保留新文本，无回答，可重试/再编辑/删除）。

### 4.3 状态迁移表（核心）

| 当前状态 | 事件 | 下一状态 | 数据/副作用 | 可见结果 |
| --- | --- | --- | --- | --- |
| 已回答 | 用户编辑并提交 | 重新生成中 | 原回答+图表标记作废；新问题文本保存 | 加载提示 |
| 重新生成中 | Agent 成功 | 已回答 | 新回答+可选图表入历史 | 展示新回答 |
| 重新生成中 | Agent 失败 | 回答失败 | 保留新问题文本 | 错误提示+重试入口 |
| 已回答 | 用户删除并确认 | 已删除（含后续轮次级联作废/删除） | 历史与上下文同步移除 | 界面收缩 |
| 回答生成中（原始提问） | 用户编辑/删除 | 待决定（见 §6.3） | — | — |

## 5. 角色、权限与数据

| 项 | 规定（建议） |
| --- | --- |
| 角色 | 单用户场景：会话所有者可编辑/删除自己会话中的任意问题。是否存在多角色/共享会话：**未知** |
| 权限边界 | 用户只能操作自己上传数据产生的会话；不可见他人会话（若产品当前为纯单用户本地工具，此项简化，需确认） |
| 数据副作用 | 编辑/删除改变对话历史与 Agent 上下文；不改动已上传的数据文件本身 |
| 费用 | 每次编辑重答消耗一次 Agent 调用；删除不消耗。额度/计费口径：**未知** |
| 数据保留 | 作废/删除内容是否保留可恢复副本：**待决定（Q4/Q6）** |

## 6. 异常与边界

| ID | 场景 | 产品行为（建议） |
| --- | --- | --- |
| X1 | 编辑后提交空文本 | 前端拦截，提示“问题不能为空”，不发起调用 |
| X2 | 编辑重答时 Agent 调用失败 | 问题保留新文本，显示失败提示与“重试/再次编辑/删除”入口；不自动无限重试（重试次数上限待决定） |
| X3 | 原始回答仍在生成中时用户发起编辑/删除 | **待决定**。建议：生成中禁止编辑/删除该轮（操作入口禁用），避免结果不明；或允许删除且中止生成。需确认 |
| X4 | 删除第一条问题 | 正常执行：整个对话只剩数据上传记录，后续提问以空上下文开始 |
| X5 | 连续快速多次编辑提交 | 后一次提交时若前一次仍在生成，建议提示等待或取消前次（并发口径待决定） |
| X6 | 删除后立即提问 | 上下文已同步更新，正常回答；验收断言回答不引用已删内容 |
| X7 | 会话/页面中断后恢复 | 对话历史持久化（是否已持久化：**未知**，若当前为内存态需新增持久化，属技术待承接） |

## 7. 验收设计（草案）

| ID | 场景 | 前置 | 操作 | 可判定断言 |
| --- | --- | --- | --- | --- |
| AC1 | 修改后重答 | 按示例完成 3 轮对话 | 编辑第 2 问为“华南地区增长最快的产品是什么？”并提交 | 第 2 问显示新文本；第 2 问下方出现针对华南的新回答；原华东回答与第 2 问原回答的图表不再展示；第 3 问（画图）按 Q1 决定作废或重答 |
| AC2 | 删除级联 | 3 轮对话 | 删除第 2 问并确认 | 第 2、3 轮问答及图表全部从界面消失；第 1 轮保留 |
| AC3 | 上下文一致性 | AC2 完成后 | 提问“刚才增长最快的产品是什么？” | 回答不引用已删的华东/华南分析，或明确说明无此前分析可引用 |
| AC4 | 空编辑拦截 | 任意已回答问题 | 清空文本提交 | 提示非空，无 Agent 调用发生 |
| AC5 | 删除确认 | 任意 | 点击删除 | 弹出确认，文案含“将同时删除其后 N 轮”；取消则无变化 |
| AC6 | 重答失败 | 模拟 Agent 失败 | 编辑提交 | 失败提示可见；问题保留；提供重试与删除入口 |

**验收环境/数据**：需一份含地区、产品、销售额、时间维度的测试数据集（具体由需求方提供或授权构造）。实际验收执行属后续阶段，本表仅为设计。

## 9. 已明确 / 建议 / 待决定 汇总

**已明确（来自开发请求）**：
- 修改后结合之前对话重新回答。
- 删除时级联删除该问题及其后续回答，并更新对话历史。

**建议方案（未经确认，不作为已定决定）**：
- 编辑=替换该轮问答，后续轮次一并作废而非自动级联重答（Q1 的推荐项）。
- 入口仅设在问题上；删除需确认弹层；图表作为回答派生物联动。
- 生成中禁止编辑/删除（X3 推荐项）。

**待需求方决定**：
- Q1 修改后后续轮次作废还是自动重答
- Q2 是否保留“已编辑”痕迹
- Q3/Q4 删除确认与撤销
- Q5 上下文长度上限与截断策略
- Q6 作废内容是否保留可恢复副本
- Q7 对话历史当前是否已持久化
- 批量删除、多角色/共享会话是否存在、调用费用口径、文本长度上限、重试次数上限

**下一问题（建议先答）**：Q1——修改问题后，其后续轮次是作废还是自动重新回答？这决定 T3–T6 的核心行为与费用模型。
