# 修改和删除历史问题

## 场景

这是一个可以用自然语言查询数据的工具。用户上传一份销售数据，就能连续提问，让 Agent 完成分析。

示例对话：

1. 用户问：“去年各地区的销售额是多少？”
2. 用户接着问：“华东地区增长最快的产品是什么？”
3. 用户再要求 Agent：“把结果画成图。”

随后用户发现第二个问题问错了，应该看华南地区。

## 开发请求

增加修改和删除历史问题的能力。修改问题后，结合之前的对话重新回答；删除问题时，同时删除这个问题及其后续回答，并更新对话历史。

## 本次要求

请制定这个项目的产品 SOP 或产品行为设计，说明：

- 用户可以在哪些位置做什么。
- 修改或删除后，问题、回答和图表各自怎样变化。
- 对话历史与 Agent 后续实际使用的上下文怎样保持一致。
- 适用状态、角色和权限。
- 正常路径、异常路径和可验收结果。
- 哪些行为已有明确规定，哪些确实需要需求方补充决定。

不要把推荐方案写成用户已经确认的决定。只输出设计与制作计划，不进入代码实现。
