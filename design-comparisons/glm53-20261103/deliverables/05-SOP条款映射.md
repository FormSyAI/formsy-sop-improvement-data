# SOP 条款与实际改善的映射

| SOP 条款 | 实际推动的设计行为 | 观察到的案例 |
|---|---|---|
| PC04 来源、假设与未知 | 区分用户原文、建议、假设、未知，不把推荐写成已确认 | 所有案例 |
| PC05 完整用户旅程 | 要求入口、前置、动作、反馈、结果和退出连续 | 设备维修锁定起点 |
| PC08 业务规则与状态 | 要求前后状态、分支、重复和冲突出入一致 | 培训重复提交、维修状态 |
| PC09 异常与边界 | 覆盖失败、重复、取消、中断、恢复和依赖不可用 | 上传失败、重答失败 |
| PC10 数据、权限与副作用 | 明确谁改什么、何时生效、有哪些外部副作用 | 预约锁定、删除上下文 |
| PC12 验收设计 | 为每个关键行为写前置、操作和可判定断言 | 维修 AC1–AC7，历史问题 SC-01–SC-09 |
| PC13 正反追踪 | 功能和验收相互对应，发现孤立功能 | 设备维修和编辑历史案例 |
| PC14 产品与技术交接 | 技术依赖没有被产品语言掩盖 | 预约系统对接、上下文重建 |
| TC04 接口契约 | 重复、超时、权限、版本和调用方一致 | 提交重试、发布流程 |
| TC06 状态与场景 | 正常、取消、重复、部分失败和恢复有场景记录 | 删除历史、重答失败 |
| TC07 技术未知 | 关键未知有影响和下一动作，未验证不能算解决 | 预约系统对接、持久化 |
| TC09 权限与副作用 | 信任边界、权限和数据副作用明确 | 单用户会话、文件访问 |
